# 双引擎过渡方案

> **关键文档**：解决"现有 100+ 商家库存发布模式 vs 新撮合模式"的冲突问题。
> 决策核心：**不建新小程序，原平台升级 + 模块化扩展 + 渐进迁移**。

## 一、问题与决策

### 1.1 现状

- 货袋子已有平台 + 微信小程序在用
- 100+ 商家已经入驻并发布库存
- 现有模式：「卖家发库存 → 买家浏览 → 直接联系」
- 新设计的模式：「买家发询价 → AI 匹配 → 多家报价 → 撮合」

### 1.2 三个备选方案对比

| 方案 | 优点 | 缺点 | 评分 |
|---|---|---|---|
| A. 原平台升级（单一） | 数据集中、用户不切换 | 改造风险 | ⭐⭐⭐ |
| B. 新建独立小程序（双轨） | 风险隔离、新功能自由 | 用户分裂、资源分散 | ⭐⭐ |
| **C. 原平台 + 双引擎模块（推荐）** | **数据共享、用户不切换、风险可控** | **设计需要清晰** | **⭐⭐⭐⭐⭐** |

### 1.3 最终决策

**采用方案 C：原平台 + 双引擎模块**

- ✅ 不建新小程序
- ✅ 不删除任何老功能
- ✅ 数据一份（库存与询价共享底座）
- ✅ 6 个月渐进过渡
- ✅ 老用户全程可关闭新功能

## 二、核心设计：「平台双引擎」

### 2.1 架构图

```
                  货袋子平台（统一）
                  ────────────────
                        ↓
         ┌──────────────┴──────────────┐
         ↓                              ↓
   引擎 A：库存展示                引擎 B：采购撮合
   （已有，保留 100%）            （新，逐步上线）
   ────────────────              ──────────────
   ✅ 卖家发布库存                ✅ 买家发起询价
   ✅ 买家浏览资源                ✅ AI 智能匹配
   ✅ 直接联系卖家                ✅ 多家报价比较
                                  ✅ 最优组合
         ↓                              ↓
         └──────────────┬───────────────┘
                        ↓
                  统一数据底座
                  ─────────────
                  - 库存数据库（保留）
                  - 卖家档案（保留）
                  - 买家档案（升级）
                  - 信用体系（新增）
                  - 交易记录（升级）
                  - 采购会话（新增）
                  - 派单引擎（新增）
```

### 2.2 关键创新：**两个引擎共享同一份数据**

```
卖家发布的每一条库存
       ↓
进入「商品池」（基础数据）
       ↓
   ┌───┴───┐
   ↓        ↓
[引擎 A]  [引擎 B]
橱窗展示  自动匹配询价
```

**卖家发一次库存，自动在两个场景被消费**：
1. 引擎 A：买家浏览时看到（原有逻辑）
2. 引擎 B：当有买家发询价时，平台优先匹配「有该库存的卖家」

**核心好处**：
- 卖家不需要"学新系统"
- 卖家发库存 = 自动接询价
- 老用户感受："我多了一份订单来源"，而不是"我要学新东西"

## 五、6 阶段过渡路线图

### Phase 0：M0 现状（不动）

```
保持现状：
  ✅ 不动任何现有功能
  ✅ 不发"重大改版"公告
  ✅ 不让卖家担忧
```

### Phase 1：M1-M2 后台准备期（无感）

```
后台默默开发：
  1. 数据底座升级（新增 33 张表）
  2. 引擎 B 模块开发（会话/匹配/AI）
  3. 接口对齐（库存数据 ↔ 询价系统）
  4. CEO 电话拜访 100 家商家（"听声音"，不宣布新功能）

老用户感知：无
```

### Phase 2：M3 灰度种子期

```
选 20-30 个 A 类种子卖家试用。

种子选择标准：
  - 入驻 ≥ 3 个月
  - 月度活跃（登录 ≥ 10 次）
  - 客户成功认为"愿意尝鲜"
  - 主营品类适合撮合

邀请话术：
  "王总，我们在测试新功能，让买家主动来询您货的价。
   您之前发的库存自动接收询价。
   完全不用学新东西。
   邀请您内测，前 30 天免费送 50 条线索包（市值 ¥1000）。"

同步种子买家：
  - 卖家反向邀请（50-100 个）
  - 2000 企微群运营精选
  - 唐山+天津地推 2 人

老用户感知：少数尝鲜者觉得"有新功能 Beta"
```

### Phase 3：M4 严格验证期

```
灰度运行 30 天后评估：
  ✅ 种子卖家保留率 ≥ 80%
  ✅ 接询价功能使用率 ≥ 50%
  ✅ 询价 → 成交转化率 ≥ 15%
  ✅ 卖家 NPS 维持
  ✅ 卖家委员会评议通过

任一不达标 → 暂停放开，先修复
```

### Phase 4：M5 半开放期

```
对所有现有 100 卖家：
  - 平台运营 1 对 1 沟通 + 培训（每家 15 分钟）
  - 默认开启「接询价」，但可关闭
  - 「老用户专属」补贴：前 60 天询价线索 5 折

对新入驻卖家：
  - 默认双模式启用
  - 新手引导：「您可以发库存 + 接询价」

老用户感知：平台升级，但非破坏性
```

### Phase 5：M6 全开放期

```
全网放开：
  - 所有用户可用双引擎
  - 小程序首页 redesign：双入口
  - 推广「智能助手」（AI 识变、清单等）
  - 卖家委员会季度评议

KPI：
  - 月撮合需求 ≥ 3000
  - 月活买家 ≥ 1500
  - 卖家月均收询价数 ≥ 10
```

### Phase 6：M9+ 深度融合期

```
库存与询价完全打通：
  - 卖家发库存时填「接询价偏好」
  - 买家询价时优先匹配「有库存」的卖家
  - 平台自动推送「类似采购需求」给已发库存卖家
  - 推出「智能定价」

商业化升级：
  - 老「会员费」改名「平台基础服务费」
  - 新增「流量费」（线索付费）
  - 新增「企业 SaaS」（针对买家）
```

## 十、商业模式过渡

### 10.1 老会员的处理

**核心原则：不动老会员的钱。**

```
现状：100+ 卖家已交年费（¥6000/年）

过渡：
  - 老会员费完全保留，期限到自然到期
  - 新功能对老会员【免费送】（前 30-60 天）
  - 续费时按新定价（¥3000 基础 + 加包）
  - 不强迫升级

升级激励：
  - 老会员"优先升级"权：原 ¥9800 黑金 → ¥6800（老用户专享）
  - 续费同时升级 → 赠送 100 条线索
```

### 10.2 新商业模式渐进引入

```
M0-M3：维持原模式
  - 会员费 ¥6000/年
  - 卖家不知道新模式存在

M3-M6：双模式并行
  - 老会员：照常用
  - 新模式给「免费试用」
  - 试用结束后老会员可选「升级」

M6-M12：新模式主导
  - 新入驻卖家：直接用新定价
  - 老会员：到期续费按新定价
  - 12 个月内全部过渡完成

M12+：完全迁移
  - 全网统一新模式
```

### 10.3 永不抽佣（红线）

无论新老模式，**永不抽交易佣金**。

## 十一、风险与对冲

### 11.1 主要风险

| 风险 | 概率 | 影响 | 对冲 |
|---|---|---|---|
| 老用户反弹"为啥要变" | 高 | 严重 | A 类 CEO 亲访 + 不动老功能 |
| 新模式数据不行 | 中 | 严重 | M3 灰度严评估 + 随时回滚 |
| 现有平台技术债务大 | 中 | 中 | Feature Flag + 微服务隔离 |
| 团队精力分散 | 高 | 中 | 明确「原平台运维」和「新模块开发」分工 |
| 老卖家发库存量下降 | 低 | 中 | 老功能保留并优化 |
| 新功能 AI 成本超预算 | 中 | 小 | 限流 + 月度预算上限 |

### 11.2 早期预警（每周看）

```
🚨 红色预警（任一即暂停）：
  - 现有 100 卖家登录率 < 80% 上月
  - 库存发布量周环比 < -20%
  - 老卖家退会员请求 > 5 家/周
  - 老卖家投诉数 > 10 条/周
  - 卖家委员会负面舆情
```

### 11.3 "随时回滚"原则

```
新模式上线后第 1-3 个月内：

任何时候，以下情况立即关闭新功能开关：
  - 老用户大规模反弹（≥20% 表达不满）
  - 新功能 NPS < 30
  - 数据异常（串价、刷量）

回滚不丢面子：
  - 对外口径："发现一些问题，暂时下线优化"
  - 不需要解释技术细节
  - 1-2 个月后再上
```

## 十二、CEO 在过渡期的角色

## 十三、决策一句话总结

> **不要建新小程序。在原货袋子小程序上做「双引擎」模块化扩展：
> 老功能（库存发布）100% 保留，新功能（采购撮合）渐进上线。
> 让卖家「不学新东西，多赚一份钱」；让买家「既能浏览也能询价」；
> 让平台「一套代码、一份数据、两个场景」。**
