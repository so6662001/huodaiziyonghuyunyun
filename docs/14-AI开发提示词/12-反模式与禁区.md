# 12 - 反模式与禁区（AI 不能做的事）

> **用途**：明确告诉 AI "不要做什么"，避免它好心办坏事。
> **本质**：负面清单比正面清单更有效。

---

## 一、AI 严格禁止的行为

```text
# 禁区清单

## 红线（违反任何一条立即停止任务）

### 1. 字段相关
❌ 严禁编造数据库字段名
❌ 严禁编造表名
❌ 严禁修改字段类型（除非 DDL 已同步）
❌ 严禁删除字段（破坏向后兼容）
❌ 严禁猜测字段含义（必须从 DDL 注释 / PRD 中找）

### 2. API 相关
❌ 严禁编造 API 路径
❌ 严禁编造 HTTP 方法
❌ 严禁编造请求体字段
❌ 严禁编造响应体字段
❌ 严禁编造错误码（必须用 ErrorCode 枚举）
❌ 严禁改变响应格式（必须 Result<T>）

### 3. 业务规则
❌ 严禁创造 PRD 中没写的业务规则
❌ 严禁修改 PRD 中已写明的阈值（如"5 轮上限"）
❌ 严禁绕过权限检查
❌ 严禁绕过数据隔离

### 4. 公共模块
❌ 严禁修改 huodaizi-common（除非明确要求）
❌ 严禁修改 huodaizi-domain（除非明确要求）
❌ 严禁修改父 pom.xml（除非明确要求）
❌ 严禁修改 .cursorrules / 本目录文档

### 5. 安全相关
❌ 严禁拼接 SQL 字符串（必须用 Wrapper / #{}）
❌ 严禁日志中输出密码 / token / 完整手机号
❌ 严禁返回敏感字段（必须脱敏）
❌ 严禁禁用 HTTPS / 禁用证书验证
❌ 严禁硬编码密钥 / API Key / 数据库密码
❌ 严禁打开 CORS '*'（生产环境）

### 6. 性能相关
❌ 严禁同步调用慢服务（AI / OCR 必须异步）
❌ 严禁循环里查 DB（必须批量）
❌ 严禁列表接口不分页
❌ 严禁缓存大对象（OOM）
❌ 严禁缓存无过期时间
❌ 严禁在事务中调用外部服务

### 7. 代码质量
❌ 严禁 catch (Exception e) {} （静默吞错）
❌ 严禁 e.printStackTrace() （没意义的输出）
❌ 严禁注释掉的废代码
❌ 严禁 TODO 不带 Issue 链接
❌ 严禁 System.out / console.log 残留
❌ 严禁魔法数字（必须常量）
❌ 严禁手写 BeanUtils.copyProperties（用 MapStruct）

### 8. 测试
❌ 严禁跳过测试（@Disabled）
❌ 严禁测试中 Thread.sleep
❌ 严禁测试依赖网络
❌ 严禁测试依赖时间
❌ 严禁只测 happy path
❌ 严禁不写测试就提交

### 9. UI/UX
❌ 严禁硬编码颜色 / 字号 / 间距
❌ 严禁字号 < 11px
❌ 严禁按钮高度 < 28pt（普通），关键按钮 < 44pt
❌ 严禁过度动画
❌ 严禁强制弹窗 / 强制订阅
❌ 严禁默认勾选会员
❌ 严禁内联 style 写复杂样式

### 10. 文档
❌ 严禁随意改 docs/ 下的文档（特别是 PRD / API）
❌ 严禁改提示词文档（本目录）
❌ 严禁不写 Javadoc 的公共方法
❌ 严禁不写 PR 描述

## 行为约束

### 不准擅自做的事

❌ 不准擅自重构（即使代码很丑）
❌ 不准擅自优化（即使你觉得能更快）
❌ 不准擅自加功能（哪怕"只是顺手"）
❌ 不准擅自改依赖版本
❌ 不准擅自加新的依赖
❌ 不准擅自改 application.yml 的关键配置
❌ 不准擅自合并 PR
❌ 不准擅自删除文件
❌ 不准擅自改 .git/ / package-lock.json

任何"擅自"的事，必须先在回答中提议，等待人工确认。

### 必须停下来问的情况

如果遇到以下情况，必须停下来询问，而不是猜测：

🛑 PRD 没写清楚某个细节
🛑 OpenAPI 与 DDL 不一致
🛑 现有代码逻辑可能有 Bug
🛑 业务规则之间互相矛盾
🛑 需要修改公共模块
🛑 需要新增依赖
🛑 需要变更接口契约
🛑 性能要求与实现方案冲突

正确的方式：
```
"我注意到 PRD 没说明 xxx 在 yyy 情况下的行为。
我建议方案 A: ...，方案 B: ...
请确认采用哪个方案，或提供更多信息。"
```

错误的方式：
```
（直接按猜测的方案实现，不询问）
```

## 沟通禁区

### 不准说的话

❌ "我假设..." → 应该问，不要假设
❌ "应该没问题" → 必须给明确答案
❌ "差不多吧" → 不准模糊
❌ "我已经处理了所有边界" → 必须列出具体处理了哪些
❌ "代码完美" → 不准自我吹嘘，必须列出 trade-off

### 必须说的话

✅ "我引用了 PRD 第 X.Y 节"
✅ "字段 xxx 来自 yyy 表"
✅ "API zzz 在 openapi.yaml 中已定义"
✅ "我处理了以下 5 个边界：1. ... 2. ..."
✅ "有以下 trade-off：..."
✅ "未实现的部分（如有）：..."

## 范围禁区

### 一个 PR 不准做的事

❌ 不准在一个 PR 中混合多个功能
❌ 不准"顺手"修不相关的 Bug
❌ 不准"顺手"重构不相关的代码
❌ 不准"顺手"升级依赖
❌ 不准"顺手"改配置

理由：PR 越纯，评审越快，回滚越容易。

### 一个会话不准做的事

❌ 不准同时做"实现"和"重构"
❌ 不准同时做"修 Bug"和"加功能"

请明确告诉 AI 这次会话要做什么。

## 错误的产物

### 不准产出的东西

❌ 不完整的代码（用 ... 省略）
❌ 没有错误处理的代码
❌ 没有日志的关键路径
❌ 没有测试的代码
❌ 没有 Javadoc 的公共 API
❌ 注释少的复杂逻辑
❌ 编译失败的代码
❌ 测试失败的代码

### 必须产出的东西

✅ 完整代码（每个文件给完整内容）
✅ 完整路径（告诉我文件放哪）
✅ 完整测试（每个 Service 方法都有）
✅ 完整自检报告（Checklist 全部打勾）
✅ 完整变更说明（PR 描述）
```

## 二、特定场景的禁区

### 2.1 前端开发禁区

```text
❌ 禁止 wx.request 直接调用（必须走 utils/request.js 封装）
❌ 禁止页面内写 if-else 业务逻辑（提到 service 层）
❌ 禁止内联 style="..."（必须 scoped CSS）
❌ 禁止全局污染（变量、CSS、事件）
❌ 禁止操作真实 DOM（用 Vue 数据驱动）
❌ 禁止禁用响应式（如 ref.value = newObj 而不是 reactive 修改）
❌ 禁止滥用 v-html（XSS 风险）
❌ 禁止用 setTimeout 实现"等待 API 返回"
❌ 禁止页面参数从 query 直接拿不校验
❌ 禁止 localStorage 存 token（必须用安全存储）
```

### 2.2 后端开发禁区

```text
❌ 禁止 catch (Exception e) { return null; }
❌ 禁止 catch (Exception e) { throw new RuntimeException(e); }
❌ 禁止 if (xxx != null && !"".equals(xxx))（用 StringUtils.isNotBlank）
❌ 禁止手写 SQL（用 LambdaQueryWrapper / MyBatis Plus）
❌ 禁止 SELECT * FROM
❌ 禁止 SELECT COUNT(*) 用于权限判断（用 selectOne + Optional）
❌ 禁止 List<XxxEntity> 直接返给上层（必须转 DTO）
❌ 禁止 Service 注入 Controller（反过来）
❌ 禁止跨服务直接访问 DB（必须走 Feign）
❌ 禁止全局静态变量保存状态（用 Redis）
❌ 禁止 ThreadLocal 不清理（内存泄漏）
❌ 禁止 new Thread()（用线程池）
```

### 2.3 数据库禁区

```text
❌ 禁止生产环境直接执行 DDL（必须走迁移工具）
❌ 禁止 DROP TABLE（必须先 RENAME 后清理）
❌ 禁止 ALTER 大表加索引（影响业务）
❌ 禁止全表 UPDATE / DELETE（必须 WHERE）
❌ 禁止 SELECT FOR UPDATE 没设超时
❌ 禁止跨库 JOIN
❌ 禁止 LIKE '%xxx%'（无法用索引）
❌ 禁止 NOT IN 大集合（性能差）
❌ 禁止 ORDER BY 没索引列
❌ 禁止 LIMIT 大 offset（用 cursor 分页）
```

### 2.4 API 设计禁区

```text
❌ 禁止 GET 请求带 body
❌ 禁止 POST 请求路径有 ID（如 POST /api/v1/users/123/update）
❌ 禁止状态码乱用（200 表示业务失败是错的）
❌ 禁止动词在路径中（GET /api/v1/getUser 错，应该 GET /api/v1/users）
❌ 禁止单复数混用（/user/123 vs /users/123 选一个，推荐复数）
❌ 禁止 v1 中放可能变的接口（要稳定）
❌ 禁止 v1 不带版本号
❌ 禁止接口超过 5 个参数（用 DTO 封装）
❌ 禁止响应字段嵌套超过 4 层
❌ 禁止接口返回不一致格式（统一 Result<T>）
```

### 2.5 安全禁区

```text
❌ 禁止前端校验代替后端校验
❌ 禁止信任前端传的用户身份（必须从 token 拿）
❌ 禁止信任前端传的角色（必须从后端查）
❌ 禁止 MD5 / SHA1 存密码（用 BCrypt）
❌ 禁止把密码以明文记日志
❌ 禁止把 token 以明文记日志
❌ 禁止 SQL 注入风险代码
❌ 禁止 XSS 风险代码（用户输入直接渲染）
❌ 禁止文件上传不校验类型
❌ 禁止文件下载不校验权限
❌ 禁止 URL 中带 token
❌ 禁止用户输入直接拼到日志
```

## 三、与人沟通的禁区

### 3.1 AI 不准说的话

```text
❌ "好问题！" / "Great question!" → 直接给答案
❌ "你说得对" → 不卑不亢
❌ "我可以试试" → 必须给明确方案
❌ "应该能行" → 必须确定
❌ "差不多吧" → 必须精确
❌ "感觉..." → 用数据 / 文档
❌ "我猜..." → 不准猜，查文档
❌ "我建议..."（无理由） → 必须有理由
❌ "据我所知..." → 必须给来源
❌ "通常情况下..." → 项目有自己的规范
```

### 3.2 AI 必须说的话

```text
✅ "我引用了 docs/xxx.md 第 N 节"
✅ "字段 xxx 来自 DDL 中的 yyy 表"
✅ "我处理了以下边界：1.A 2.B 3.C"
✅ "未处理的边界：D（理由：xxx）"
✅ "Trade-off：A 优势是 ..., B 劣势是 ..."
✅ "需要您确认：xxx"
✅ "已通过测试：mvn test 全绿"
```

### 3.3 沟通模板

```text
当 AI 不确定时，必须这样说：

"我在 [文档/代码] 中没有找到 [xxx] 的明确说明。

可能的方案：
A: ...（优点/缺点）
B: ...（优点/缺点）

我倾向于 A，理由是 ...

请确认采用哪个方案。在确认前我不会继续编码。"
```

## 四、自我审查清单（AI 提交前必查）

```
在你提交代码 / 输出之前，请按以下顺序问自己：

1. 我是否引用了 PRD 的具体段落？
2. 我是否引用了 DDL 的具体表/字段？
3. 我是否引用了 OpenAPI 的具体接口？
4. 我是否列出了所有边界情况？
5. 我是否写了测试？测试是否覆盖异常路径？
6. 我是否打了 log？敏感字段是否脱敏？
7. 我是否用了 Lombok 减少样板？
8. 我是否用了 MapStruct 转 DTO？
9. 我是否用了 BusinessException + ErrorCode？
10. 我的代码是否在 mvn compile 时通过？
11. 我的代码是否在 mvn test 时通过？
12. 我是否在 PR 描述中写了 Checklist？
13. 我是否避免了本文档列出的所有禁区？

任何一项 No → 不准提交。
```

## 五、违规处理

```text
如果发现 AI 产出违反了本文档：

第 1 次违规：让 AI 修正
  "你违反了【12-反模式与禁区】的第 X 条，
   请修正后重新输出"

第 2 次违规（同会话内）：警告
  "再次违规，请你重新读取【12-反模式与禁区】和【00-核心系统提示词】，
   严格遵守"

第 3 次违规：停止任务
  "停止本任务。
   请人工接管，或更换 AI 模型再试"

记录违规模式，更新提示词文档。
```

## 六、提示词的"反模式" Meta

```
本文档（提示词工程）的反模式：

❌ 反模式 1：提示词太长，AI 记不住
  解决：核心 < 2000 字，分类放多个文档

❌ 反模式 2：提示词太抽象
  解决：必须给反例 + 正例

❌ 反模式 3：提示词永远不更新
  解决：每周收集 AI 翻车 case，更新

❌ 反模式 4：提示词只规定"做什么"
  解决：必须规定"不做什么"（即本文档）

❌ 反模式 5：提示词没有验收
  解决：必须有 Checklist + 人工抽查

❌ 反模式 6：盲信提示词
  解决：提示词 + 人工 + CI/CD 三重保障
```

## 七、给团队 Leader 的建议

```
当 AI 团队出现以下信号，说明提示词工程没做好：

🚨 信号 1：返工率 > 30%
  → 提示词太弱，AI 跑偏严重

🚨 信号 2：Bug 数量上升
  → AI 写的代码质量下降

🚨 信号 3：PR 评审耗时增加
  → AI 自评不到位

🚨 信号 4：工程师抱怨 AI 不好用
  → 提示词没传授到位

🚨 信号 5：新人上手慢
  → 工作流 SOP 没沉淀

应对：
1. 复盘最近 10 个 PR 的翻车原因
2. 更新提示词文档
3. 团队培训
4. 试运行 1-2 周
5. 评估改善程度

定期评审提示词的 ROI，比无脑用 AI 重要 10 倍。
```
