# 17 - AI 不能漏的 50 件事（铁律）

> 基于钢贸 B2B 项目特点 + AI 编程常见翻车场景，列出 50 条铁律。
> **每一条都是血泪经验**：不遵守必然出 Bug，严重影响交付质量。

---

## A 类：字段与数据（10 条）

```
A01 字段名严格 camelCase（JSON/JS/Java）/ snake_case（SQL）
    → 杜绝 sessionId vs session_id 混用

A02 所有 id 字段统一加业务前缀
    → u_xxx / c_xxx / ps_xxx / pl_xxx / q_xxx / o_xxx
    → 严禁裸 UUID 或纯数字

A03 时间字段 ISO 8601 + 时区
    → "2026-05-27T14:00:00+08:00"
    → 严禁 "2026/05/27 14:00:00" 或 时间戳数字

A04 金额字段 BigDecimal（Java）/ Decimal（DB）
    → 严禁 float / double（精度问题）
    → JSON 中 保留 2 位小数："3920.00"

A05 数量必须 quantity + quantityUnit 分开
    → 不能 "50 吨" 字符串
    → 必须 quantity=50, quantityUnit="ton"

A06 枚举值用 snake_case 字符串
    → status="dispatching" 不是 "Dispatching" 或数字 2
    → 全平台统一枚举值

A07 多规格 items 必须是数组
    → 即使 items.length === 1 也是数组
    → 严禁退化为单值

A08 itemNo 增删后保持稳定
    → 删除 [1,2,3,4] 中的 2 → [1,3,4]（不重排）
    → 新增追加为最大号 + 1

A09 整单字段与行级字段严格分层
    → 整单：defaults / splitStrategy / note
    → 行级：itemNo / productType / quantity / 行级覆盖

A10 敏感字段必须脱敏
    → 手机号显示 138****1234
    → 身份证显示 11010119****1234
    → 银行卡显示 6228 **** **** 1234
```

## B 类：API 与契约（10 条）

```
B01 路径必须在 openapi.yaml 中定义
    → AI 严禁自创路径
    → 改动必须先改 openapi.yaml 再写代码

B02 HTTP 方法语义化
    → GET 查询 / POST 创建 / PATCH 部分修改 / PUT 整体替换 / DELETE 删除
    → 严禁 POST /api/v1/getXxx 这种伪 GET

B03 路径用复数 + ID
    → /api/v1/sessions/{id} 正确
    → /api/v1/session/{id} 错误（缺复数）
    → /api/v1/getSession/{id} 错误（带动词）

B04 响应统一 Result<T>
    → { code, message, data, requestId, timestamp }
    → 严禁裸返回对象

B05 错误码统一 ErrorCode 枚举
    → throw new BusinessException(ErrorCode.SESSION_NOT_FOUND)
    → 严禁自由字符串

B06 列表接口必须分页
    → cursor-based（pageToken + pageSize）
    → 默认 20，最大 100
    → 响应必须含 total、hasMore、nextPageToken

B07 创建接口必须支持幂等
    → 接收 Idempotency-Key 头 或 clientTempId 字段
    → 5 分钟内重复请求返回相同结果

B08 接口必须 @SaCheckLogin
    → 除登录、注册外
    → 数据隔离从 SecurityUtils.currentUserId() 拿

B09 接口必须 @Valid 校验
    → Request DTO 用 Jakarta Validation 注解
    → 校验失败统一 400 响应

B10 接口必须 @Operation + @Tag
    → 自动生成 Swagger 文档
    → 描述准确，便于前端对接
```

## C 类：业务规则（10 条）

```
C01 PRD 没说的规则严禁自创
    → 找不到就问，不要"我觉得"
    → AI 必须引用 PRD 章节

C02 议价 5 轮上限（硬规则）
    → 超过自动关闭议价

C03 会话变更 5 次上限（硬规则）
    → 超过弹出"建议新建会话"

C04 报价有效期 60 分钟默认
    → 可配置 30-120 min
    → 过期自动失效

C05 派单 30 min 无报价自动扩池
    → 第 1 次扩池：邻近省
    → 第 2 次扩池：全国

C06 锁价持续 60 min
    → 不付款自动解锁
    → 释放回派单池

C07 单清单最多 100 行规格
    → 超过提示"请拆分"

C08 卖家信用 < 60 不参与高价值池派单
    → 自动降级到 pilot 池

C09 围猎检测：5 卖家相同 IP 同时报价
    → 自动标记 + 人工复审

C10 申诉 48h 内必须闭环
    → 超时自动升级到运营主管
```

## D 类：UI 设计规范（10 条）

```
D01 颜色仅用 Token 定义的值
    → --primary / --warning / --success / --danger / --gold ...
    → 严禁 #1234XX 硬编码

D02 字号仅用 11/12/13/15/16/18/22/24 px
    → 严禁 14px / 17px 等中间值

D03 间距是 4 的倍数
    → 0/4/8/12/14/16/20/24/32/40/48
    → 严禁 10/15/22 px

D04 按钮高度有标准值
    → PC: 28/36/44
    → 移动: 28/36/44/56（关键 CTA ≥ 44）

D05 圆角有标准值
    → 0/4/6/8/12/16/9999（圆形）

D06 状态必须有 5 种以上视觉态
    → 默认 / 加载（骨架屏）/ 空 / 错误 / 成功

D07 移动端关键按钮 ≥ 44pt
    → 钢贸老板手指粗
    → 否则点击困难

D08 错误提示是人话
    → "网络不好，请重试"（✓）
    → "ERR_CONNECTION_REFUSED"（❌）

D09 数字千分位 + 单位
    → ¥1,234,567 / 50 吨 / ¥3,920/吨

D10 时间相对显示
    → "3 分钟前"、"昨天"、"上周"
    → 而不是 "2026-05-27 14:23:45"
```

## E 类：多规格场景（10 条）

```
E01 默认即多规格录入
    → 发需求页打开就是多行表单
    → 不是"单条 + 高级选项"

E02 行内增删改不弹窗
    → 直接在列表内编辑
    → Excel 体验

E03 每行独立状态
    → 不能整单状态覆盖行级
    → 6 种行级状态完整支持

E04 卖家可勾选可供货行
    → 部分供货 / 部分数量
    → 不能强制"全报或不报"

E05 报价矩阵展示所有 N×M
    → PC 端必须完整矩阵
    → 移动端按行 Top 3

E06 AI 识变定位到行
    → "3 号规格再加 20 吨" → itemNo=3
    → 不能整单变更

E07 行级独立成交
    → 5 行先锁，剩余 3 行继续找
    → 不阻塞已成交行

E08 拆单 3 种策略必须实现
    → auto / bundle / manual

E09 行级状态变化触发事件
    → 行级 status 变 → 推送对应卖家
    → 而不是整单一次性推

E10 文案统一用"清单"而不是"询价"
    → 强调多规格属性
    → "8 行规格清单" vs "1 个询价"
```

## F 类：安全与性能（10 条）

```
F01 密码用 BCrypt
    → 严禁 MD5 / SHA1 存密码

F02 SQL 严禁字符串拼接
    → 用 LambdaQueryWrapper / #{} 占位符
    → 严禁 + 拼 user.name

F03 文件上传校验
    → 类型白名单 / 大小 ≤ 10MB / 文件名过滤

F04 接口频控
    → 短信发送：60s / 1 次
    → 登录：5 min / 5 次
    → 询价创建：1 min / 10 次

F05 日志严禁敏感字段
    → 严禁打印 密码 / token / 完整手机号
    → 必须脱敏：log.info("用户登录: phone={}", desensitize(phone))

F06 列表查询必须有索引
    → 写 SQL 前查 DDL 的 INDEX 定义
    → 没索引必须先加

F07 高频读必须缓存
    → Redis 缓存 + 过期 + 防穿透/雪崩
    → key 设计合理

F08 慢服务必须异步
    → AI 调用 / OCR / 通知 → 走 RocketMQ
    → 严禁同步调用阻塞接口

F09 严禁在 @Transactional 中调用外部服务
    → 长事务 → DB 连接耗尽

F10 N+1 查询必须改批量
    → 循环里查 DB → 必须 IN (...) 或 join
```

## 使用方式

### 方式 1：在每次 AI 对话开始时

```
你正在开发货袋子 [模块/功能]。

在编码前，请回顾并承诺遵守 docs/14-AI开发提示词/17-AI不能漏的50件事.md 的所有 50 条铁律。

特别关注本次任务相关的：
- A01-A10：[如涉及字段]
- C01-C10：[如涉及业务规则]
- E01-E10：[如涉及多规格]
```

### 方式 2：在 Code Review 时

```
请按 docs/14-AI开发提示词/17-AI不能漏的50件事.md 逐条 review 这个 PR：

逐条输出：
□ A01 字段名规范 - 是否合规？
□ A02 ID 前缀 - 是否合规？
...

发现违反任何一条 → 列出 + 修复建议
```

### 方式 3：在 PR 描述中

```
## 50 条铁律自检

| 类别 | 涉及条目 | 合规情况 |
|---|---|---|
| A 字段 | A01,A02,A04,A07 | ✓ 全部 |
| C 业务 | C03,C07 | ✓ 全部 |
| E 多规格 | E01,E03,E07 | ✓ 全部 |
| ... | | |

剩余 N 条不涉及本 PR。
```
