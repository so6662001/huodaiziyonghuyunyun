请按以下顺序工作（不要直接改代码）：

## Step 1：根因分析

请回答：
1. 直接原因是什么？（哪一行代码、哪个变量为 null / 哪个条件错）
2. 根本原因是什么？（为什么会出现？设计缺陷？边界遗漏？竞态条件？）
3. 是否有相似问题（同一根因可能引发其他 Bug）？
4. 这个 Bug 何时引入的？（git blame）

## Step 2：影响评估

1. 多少用户受影响？
2. 数据是否已损坏？需要修复脚本吗？
3. 是否需要紧急回滚？
4. 是否影响其他功能？

## Step 3：修复方案

提供至少 2 个方案：

方案 A：[描述]
- 优点：...
- 缺点：...
- 风险：...

方案 B：[描述]
- 优点：...
- 缺点：...
- 风险：...

推荐：方案 X，理由：...

## Step 4：实现修复

按推荐方案修复。

⚠️ 最小改动原则：
- 只改有问题的地方
- 不要"顺手"重构
- 不要"顺手"加功能

## Step 5：回归测试

必须新增至少 1 个测试用例，确保此 Bug 不再出现：

```java
@Test
@DisplayName("[Bug ID] 复现场景 - 修复后应正常")
void test_bug_xxxxx_fixed() {
    // Arrange：构造能触发 Bug 的输入
    // Act：调用方法
    // Assert：断言行为符合期望（不是抛异常）
}
```

## Step 6：验证

请确认：
1. 本地能复现 Bug 吗？（应用修复前）
2. 应用修复后，复现步骤是否已解决？
3. mvn test 全绿？
4. 关键功能是否还正常？
