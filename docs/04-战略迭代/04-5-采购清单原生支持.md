# 采购清单原生支持

> 解决 B2B 平台第五个生死命门：真实采购清单是几十行 Excel/PDF/纸质，让采购员一行行在平台填，没人愿意用。

## 一、问题本质

真实采购清单的几种形态：

### 形态 A：甲方/客户发来的工程清单（最常见）

```
《XX 工程钢材采购清单》

序号 品名   材质    规格              数量    到货地  交期
1   热轧板 Q355B  10×2000×6000     25 吨   天津    6/1
2   热轧板 Q355B  12×2000×6000     18 吨   天津    6/1
3   热轧板 Q235B  8×1500×6000      32 吨   天津    6/3
4   H 型钢 Q345B  HM350×175        15 吨   天津    6/5
5   H 型钢 Q345B  HW200×200        8 吨    天津    6/5
6   角钢   Q235B  L100×100×8       5 吨    天津    6/5
...
（20-50 行）
```

### 形态 B-E
- 自家技术员的物料单
- 上一笔生意改一改
- 纸质单/PDF 扫描件
- 手机拍的清单照片

### 让采购员一行行填的代价

```
50 行清单 × 每行 6 个必填字段 × 平均 8 秒/字段 = 2400 秒 = 40 分钟
```

**没有任何一个采购员愿意花 40 分钟填一张单。微信里 30 秒发一张图就完事了**。

## 二、战略原则

**不要让采购员"适应平台的结构化数据"，让平台"适应采购员的原生工作物"。**

- 采购员手里有什么，**平台就接受什么**（Excel / PDF / 图片 / 微信转发的图）
- 解析、整理、匹配的活，**平台全干**
- 采购员只做：**上传 → 等结果 → 选方案**

## 三、12 个具体机制

### 机制 1：「清单原物上传」拍照/转发即询价

```
买家进入"发清单"页：

┌──────────────────────────────────────┐
│  请上传您的采购清单                    │
│                                      │
│  📷 拍照（最常用）                    │
│  📁 上传 Excel/PDF                   │
│  📋 粘贴 Excel 内容                  │
│  💬 转发自微信（一键导入聊天记录）     │
│  ✏️  手动新建                         │
└──────────────────────────────────────┘
```

#### A. 拍照上传（首选）
- 采购员桌上一张甲方发来的纸质单，拍一张照片，上传
- 5 秒钟完成
- 支持多角度、有光斑、有阴影的真实手机拍摄
- 后台 OCR + LLM 自动解析

#### B. Excel/CSV 上传（无格式要求）
- **不要求固定模板**——你 Excel 长什么样都接
- 自动识别表头
- 支持合并单元格、空行、批注等"脏数据"

#### C. PDF 上传
- 工程清单、合同附件常见格式

#### D. 微信转发导入
- 采购员经常在微信群里收到清单图片
- 提供"微信内一键转发到货袋子"（通过企微生态）

#### E. 粘贴文本
- 从 Excel/网页复制几行数据，直接粘贴

### 技术实现

```
拍照/上传文件
   ↓
OCR（百度智能云/阿里 OCR/腾讯 OCR）
   ↓
LLM 解析（GPT/通义千问，结构化提取）
   ↓
槽位填充：[品名, 材质, 规格, 数量, 到货地, 交期]
   ↓
人工校验页（买家快速确认）
   ↓
进入"清单会话"系统
```

**关键：5-10 秒内完成解析**。

### 机制 2：「智能解析 + 极简确认」

错误设计：让用户**逐行确认**。

正确设计：

```
上传清单后，展示解析结果：

📋 已识别 23 行物料（点击折叠查看明细）

⚠️ 我有 2 行不确定，请您看一下：
  - 第 7 行："角钢 L100×8" → 我猜是 "L100×100×8"，对吗？
  - 第 18 行："螺18 20T" → 我猜是 "螺纹 HRB400 ¢18 20 吨"，对吗？

[全部正确，发起询价]  [查看明细]
```

**关键**：

- AI 自信的不让用户看（90% 行直接通过）
- AI 不确定的才弹出确认（10% 行）
- 批量"全部正确"按钮，10 秒搞定

### 机制 3：「智能拆单」一份清单 → 多个卖家专精响应

```
清单 #001（共 23 行）

平台自动拆分为：
📦 板材部分（10 行，板材专精卖家可见）
📦 型材部分（5 行，型材专精卖家可见）
📦 螺纹部分（5 行，螺纹专精卖家可见）
📦 角钢部分（3 行，型材专精卖家可见）

派单：
- 板材给唐山板材卖家 Top 15
- 型材给唐山型材卖家 Top 10
- 螺纹给唐山螺纹卖家 Top 12
```

### 机制 4：卖家端"部分应答"

```
卖家收到的是"我能供的部分"：

🔔 新清单询价：23 行物料，您可能能供 10 行（板材部分）

[查看明细] [接单] [拒单]

接单后：
  逐行查看，可"勾选 + 报价"：
  ☑ 1. 热轧板 Q355B 10×2000×6000  25 吨  ¥4350/吨
  ☑ 2. 热轧板 Q355B 12×2000×6000  18 吨  ¥4320/吨
  ☐ 3. 热轧板 Q235B 8×1500×6000   32 吨  [我不报]
  ☑ 4. ...

  [批量同价]  [Excel 模板下载/上传报价]  [提交]
```

**关键**：允许"部分应答"，**不强迫"全包才能接单"**。

### 机制 5：「卖家批量报价工具」

卖家端提供三种方式：

#### 方式 A：直接在 App 里批量填（适合 5-10 行）

```
┌────────────────────────────┐
│ 全选 │ 同价 ¥[____]/吨    │
│ ☑1  │ 已填  ¥4280         │
│ ☑2  │ 已填  ¥4280         │
└────────────────────────────┘
一键批量同价
```

#### 方式 B：下载 Excel 模板填好上传（适合 20+ 行）

- 卖家点击"下载报价模板"
- 模板已含清单所有行 + 卖家信息
- 卖家填好后上传
- 平台 5 秒解析

#### 方式 C：语音批量报（实验性）

- 卖家对着 App 说："1-5 行都是 4280，6-10 行 4320"
- AI 解析后展示，卖家确认

### 机制 6：「最优组合算法」平台真正的价值高地

```
平台自动计算"最优组合方案"：

方案 A：成本最低（综合最便宜）
   - 卖家 A 供 10 行（板材）
   - 卖家 B 供 5 行（螺纹）
   - 卖家 C 供 8 行（型材+角钢）
   总价：¥123.5 万
   总卖家数：3 家

方案 B：管理最省事（一家通包）
   - 卖家 D 一家全供 23 行
   总价：¥128 万（+3.6%）
   总卖家数：1 家

方案 C：交期最快
方案 D：信用最高

[选择方案 A]  [选择方案 B]  ...  [自定义组合]
```

**这是 Excel/微信完全做不到的事**——这是平台的杀手锏。

### 机制 7：「清单 = 长期项目档案」不只是询价，是项目管理

```
项目：XX 工程钢材采购
   ├── 5/23 询价清单（23 行）→ 成交 1 期
   ├── 6/5 补单（10 行）→ 成交 2 期
   ├── 6/20 补单（5 行）→ 成交 3 期
   └── 项目总览：累计 ¥350 万，已交付 80%

操作：
- [复制清单到新项目]
- [追加补单]
- [导出项目台账]
- [生成项目对账单]
- [项目结算]
```

**这是让公司付费 ¥3000-¥10000/年 的产品形态**：项目管理 SaaS，而不是询价工具。

### 机制 8：「卖家"专精清单"功能」卖家不被"全清单"骚扰

- 卖家设置"我专供的品类"
- 平台拆单后只把"匹配品类"的部分给卖家
- 卖家收到的是"3 行板材"而不是"23 行混合"

### 机制 9：「清单的"模糊询价"」不要求一开始就精确

```
上传清单时可选模式：

🎯 精确询价（清单已定）
   → 卖家给精确报价

🌫️ 模糊询价（清单待定）
   → 让卖家先报"参考价"
   → 不约束卖家最终成交时调整
   → 用于"摸底"
   → 标记给卖家：这是"参考询价"
```

### 机制 10：「企微版"清单助手"」上传搬到微信

```
采购员在企微里发清单图片到群里：
   ↓
@货袋子小助手 解析这张清单
   ↓
机器人 5 秒后回：
   "已识别 23 行物料，是否发起询价？
    [发起询价] [查看清单]"
   ↓
点击发起 → 后续询价、报价、对比全在企微小程序里完成

微信原生场景：
甲方在微信里发给采购员一张清单 PDF
   ↓
采购员长按 PDF → 选择"用其他应用打开"
   ↓
弹出"货袋子" → 一键导入
```

### 机制 11：「报价对比导出」给采购员的"工作交付物"

```
[导出比价单 PDF]
   ↓
生成正式格式：
《XX 项目钢材采购询价比对单》
- 清单概要
- 5 家卖家报价对比表
- 最优组合方案
- 我的推荐方案
- 平台认证印章

下载/打印/转发给老板
```

**采购员"用平台 = 工作交付物自动生成"**——这是采购员愿意主动用平台的根本原因。

## 四、清单与"采购会话"的融合

```
清单上传
   ↓
平台自动解析 + 智能拆单
   ↓
为每个品类生成独立的"采购会话"
   ↓
每个会话独立进行报价、议价、变更
   ↓
最终在"清单聚合视图"展示所有会话的状态
   ↓
平台计算"最优组合"
   ↓
买家选择方案 → 成交
```

**清单 = 多会话的容器**。

## 五、对比微信发清单

| 维度 | 微信发清单 | 货袋子（新模型） |
|------|---------|--------------|
| 上传 | 转发图片 | 转发图片（一样） |
| 接收方 | 1 个熟悉的卖家 | 自动匹配 N 家 |
| 卖家反应 | 看图→打电话问→回复 | 5 秒内开始报价 |
| 比价 | 卖家一家一家来，自己脑算 | 平台自动比对 + 最优组合 |
| 变更 | 反复发新图 | 一键修改+同步 |
| 沉淀 | 几天后聊天记录就找不到 | 项目档案永久保存 |
| 汇报 | 自己整理 Excel | 一键导出 PDF |
| 适用场景 | 1 家熟卖家 | 多家+新供应商 |

**关键洞察**：微信适合"1 个熟卖家"，**平台适合"找多家+新供应商"**。两者互补，不冲突。

## 六、技术能力清单

| 能力 | 实现方式 | 难度 |
|------|--------|------|
| OCR 识别 | 阿里/腾讯/百度 OCR API | 低 |
| Excel/PDF 解析 | 开源库 + 自研 | 中 |
| 清单结构化（文字→字段） | LLM | 中 |
| 智能拆单 | 规则引擎 + LLM | 中 |
| 最优组合算法 | 运筹学（线性规划） | 高 |
| 微信转发导入 | 企微开放 API | 中 |
| 清单模板/项目管理 | 后端业务逻辑 | 低 |

## 八、终极战略心智

> **采购员手里有什么（清单照片、Excel、纸质单），平台就接受什么。
> 解析、拆单、撮合、比价、汇报，平台全干。
> 采购员只做三件事：上传 → 选方案 → 下单。
> 微信里能做的事继续在微信里做，
> 微信里做不到的事（多家比价、最优组合、项目管理、合规汇报）让平台做。**

## 九、最终战略转向（贯穿全文）

**货袋子不应该把自己定位成"撮合平台"，应该定位成"中小钢贸采购员的 AI 工作助手"**。

| 旧定位 | 新定位 |
|------|------|
| B2B 撮合平台 | AI 采购助手 |
| 卖家入驻 + 买家询价 | 帮采购员搞定他的本职工作 |
| 比价工具 | 工作交付物生成器 |
| 流量生意 | SaaS 生意 |

这个定位下：
- 买家来不是为了"找便宜的"，是为了"省时间、做汇报、管项目"
- 平台的真实价值是"采购员的同事"
- 钱来自"工具费/服务费"，不是"撮合佣金"
- 和微信、电话、找钢网都不竞争（它们都是工具，平台是"采购员的桌面"）
