> **目的**：双引擎过渡期实时监控数据。**每周一会议必看**。

```
飞书多维表格"货袋子运营 KPI 看板"

  ├── 看板 2：100 家商家分层健康度（运营）

  ├── 看板 6：技术健康（CTO）
  └── 看板 7：竞争对标（CMO）
```

| 备注 | 长文本 | 关键反馈/动态 |

### 健康度计算规则

```
🟢 良好（85+ 分）：
  - 月登录次数 ≥ 10
  - 新功能已开通
  - 月报价数 ≥ 5
  - 无投诉

🟡 关注（60-84 分）：
  - 月登录 5-9 次
  - 新功能未开通或有疑虑
  - 报价数 1-5

🔴 危险（<60 分）：
  - 月登录 < 5 次
  - 新功能已关闭或退会员
  - 0 报价
  - 有投诉
```

### 看板视图

```
视图 1：所有商家（默认）
  按分层 + 健康度排序

视图 2：A 类（CEO 看）
  仅显示 A 类，按健康度筛

视图 3：本周待联系
  状态 = "待联系"，按 Owner 分组

视图 4：风险预警
  健康度 = "🔴 危险"，必须 24h 内处理

视图 5：流失追踪
  状态 = "流失"，分析原因
```

| 响应率周环比 | 百分比 | 红色预警 < -20% |
| 报价方差 | 百分比 | < 1% 疑似串价 |
| 退会员请求数（本周） | 数字 | > 5 红色 |
| 商会舆情 | 颜色 | 🟢 / 🟡 / 🔴 |
| 头部卖家停止登录天数 | 数字 | > 7 天预警 |
| 跨区成交占比 | 百分比 | > 10% 黄色 |
| 当前预警级别 | 颜色 | 🟢 / 🟡 / 🔴 / 🟣 |

### 预警阈值

```
🚨 紫色（最高级，CEO 立即介入）：
  - 商会发函或公开质疑
  - 卖家间私信"抵制货袋子"
  - 主流媒体负面报道

🚨 红色（24h 内处置）：
  - 区域响应率突降 > 20%/周
  - 退会员请求 > 5 家/周
  - 报价方差 < 0.5%（疑似串价）

🟡 黄色（72h 内调查）：
  - 头部卖家停止登录 > 7 天
  - 跨区成交占比 > 10%
  - 报价方差 < 1%
```

### 处理流程

```
触发红色预警：
  T+0     系统自动告警
  T+4h    运营负责人 + CEO 紧急会议
  T+24h   重点卖家逐一电话沟通
  T+48h   出整改方案
  T+72h   召开卖家委员会临时会议
  T+1w    回到正常运营
```

## 九、自动化机制

### 1. 数据来源

```
自动同步（每小时/天）：
  - 业务数据库 → 飞书表格（API）
  - 第三方服务（行情/钢联）→ 飞书表格
  - 监控系统（Prometheus）→ 飞书表格

人工录入：
  - 卖家访谈反馈
  - 商会舆情
  - 重大事件
```

### 2. 自动告警

```
触发条件 → 自动通知（钉钉/企微）：

  红色预警 → CEO + CTO + 相关 VP 群
  黄色预警 → 运营负责人 + 相关人
  指标偏离 → 对应 Owner

通知频率：
  红色：立即 + 每 30 分钟重复
  黄色：立即 + 每 2 小时重复
  日报：每天 9:00
  周报：每周一 9:00
  月报：每月 1 号 10:00
```

### 3. 看板权限

| 看板 | 可查看 | 可编辑 |
|---|---|---|
| 1 业务核心 | 全员 | CEO/COO |
| 2 商家分层 | 全员 | 客户成功 + 运营 |
| 3 新功能漏斗 | 产品 + CEO | 产品 |
| 4 财务影响 | CEO/CFO/CTO | CFO |
| 5 区域监控 | 全员 | 风控 + 运营 |
| 6 技术健康 | 技术 + CEO | CTO |
| 7 竞争对标 | CEO + CMO + 投资人 | CMO |

## 十、看板创建步骤（飞书操作）

### Step 1：创建多维表格

```
1. 飞书 → 新建多维表格 → 命名"货袋子运营 KPI 看板"
2. 创建 7 个数据表（对应 7 个看板）
3. 按上述字段定义建表
```

### Step 2：导入初始数据

```
1. 从业务数据库导出 CSV
2. 飞书表格导入
3. 设置字段类型
```

### Step 3：配置自动同步

```
通过飞书开放平台 API：

POST https://open.feishu.cn/open-apis/bitable/v1/apps/{app_token}/tables/{table_id}/records
  body: { records: [...] }

定时任务（每小时）：
  - 从业务 DB 跑 SQL
  - 转 JSON
  - 调飞书 API 同步
```

### Step 4：配置仪表盘

```
1. 在每个数据表中点击"仪表盘"
2. 添加卡片：数字 / 柱状图 / 折线图 / 饼图
3. 设置数据源（来自表格字段）
4. 设置筛选条件
5. 一键分享给团队
```

### Step 5：配置告警

```
1. 飞书表格 → 自动化流程
2. 触发条件：字段值变更（如健康度 = 🔴）
3. 动作：发消息到指定群
4. 测试 + 上线
```

## 十一、使用节奏

```
每天 9:00：
  自动日报推送到"货袋子运营群"
  显示：核心指标 + 红色预警

每周一 10:00 KPI Weekly（30 分钟）：
  全员 review 7 个看板
  红黄预警立即处置

每月 1 号 14:00：
  月度业务回顾（2 小时）
  全员看板深度复盘

每季度末：
  季度战略对齐（半天）
  含卖家委员会评议
```

## 十二、给团队的承诺

```
1. 数据透明：所有看板对应可查看的角色公开
2. 实时性：核心数据每小时更新
3. 责任制：每个红色指标都有 Owner
4. 复盘机制：每月对未达标指标做复盘
5. 持续改进：每季度优化看板字段
```
