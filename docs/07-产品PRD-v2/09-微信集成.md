# M9：微信集成 ⭐

> 货袋子的"杀手锏"。终极原则：**不要试图把用户从微信拉出来，而是把平台搬进微信**。

## 1. 模块目标

让买家/卖家完全在微信生态里完成所有操作：

- 微信小程序 = 主战场
- 企微机器人 = 群内询价入口
- 微信转发导入 = 清单上传通道
- 虚拟号中继 = 通话留痕
- 企微群 SCRM = 客户运营工具

**对比**：

| 工具 | 阻力 | 货袋子解法 |
|---|---|---|
| 用户在微信 | I-1 微信生态绑定 | 平台搬进微信 |
| 打电话最有效 | I-2 关系生意 | 虚拟号中继，保留电话体验 |
| 清单在微信转发 | B-C2 清单填不动 | 转发即识别 |
| 老板用企微 | 沟通深度 | 企微群机器人 |

## 2. 子模块 1：微信小程序

### 2.1 架构

```
货袋子主小程序（订阅号 + 服务号）
  ├── 买家视图
  │   ├── 发需求（极简/语音/拍照）
  │   ├── 我的采购会话
  │   ├── 行情中心
  │   └── 我的供应商
  ├── 卖家视图
  │   ├── 我的接单
  │   ├── 我的客户 CRM
  │   ├── 我的报价
  │   └── 我的收益
  └── 共用
      ├── 我的（个人账户）
      ├── 消息中心
      └── 设置
```

### 2.2 关键能力

- 微信登录（unionid 绑定）
- 微信支付（仅 SaaS/订阅，不涉及交易）
- 微信分享卡片（采购会话、报价对比）
- 微信转发文件（清单图片/PDF → 一键导入）
- 微信群机器人（详见子模块 2）
- 服务号模板消息（推送）

## 3. 子模块 2：企微机器人

### 3.1 使用场景

```
采购员在他常用的钢贸微信群里：

  采购员：@货袋子小助手 我要 50 吨热轧 Q235B 5.5 到天津

  小助手 5 秒后回：
  ┌──────────────────────────────────┐
  │ 已发起采购会话 #20260523001       │
  │ 品名：热轧卷板 Q235B 5.5mm        │
  │ 数量：50 吨 → 天津                 │
  │ 匹配中... 预计 10 分钟内 5+ 报价  │
  │ [查看会话]                        │
  └──────────────────────────────────┘

  10 分钟后机器人 @ 采购员：
  ┌──────────────────────────────────┐
  │ 您的会话有 6 家报价，最低 ¥4260  │
  │ [一键查看]                        │
  └──────────────────────────────────┘
```

### 3.2 命令体系

```
@货袋子小助手 + 自然语言

支持的命令：
  - 发需求："我要 50 吨热轧 5.5 到天津"
  - 查询行情："今天热轧多少钱"
  - 查询订单："我的订单"
  - 改需求："上次那个改成 80 吨"
  - 查找卖家："唐山做螺纹的"
  - 投诉："我要投诉 XX 卖家"

底层用 LLM 解析意图，规则引擎兜底
```

### 3.3 群机器人 vs 私聊机器人

```
群机器人：
  - 群里 @ 触发
  - 默认不主动发言
  - 群主可关闭
  - 用于"快速询价 + 通知"

私聊机器人：
  - 1 对 1 私聊
  - 可主动推送（成交通知/报价提醒）
  - 用于"深度操作"
```

### 3.4 推送策略

```
仅在用户明确开启时推送：

紧急通知（须用户开启）：
  - 卖家报价到达
  - 卖家议价回应
  - 卡片变更提醒
  - 投诉处理结果

日常通知（合规推送）：
  - 早 8:00 行情快报（可关闭）
  - 老客户通道续单提醒
  - 周度收益报告（卖家）

禁止：
  - 营销骚扰
  - 第三方广告
  - 高频骚扰（同一用户 24h ≤ 5 次推送）
```

## 4. 子模块 3：微信转发导入

### 4.1 场景

```
甲方在微信里发给采购员一张清单 PDF
   ↓
采购员长按 PDF
   ↓
"分享到 → 货袋子小程序"
   ↓
弹出确认页 + 自动解析
   ↓
进入清单确认流程（详见 M3）
```

### 4.2 支持的文件类型

- PDF（清单/合同附件）
- 图片（拍照清单 / 截屏）
- Excel（采购单）
- Word（少见，作兜底）

### 4.3 技术实现

```
微信开放接口：
  - openSDK 文件分享
  - 文件 hash 校验
  - 文件大小限制：< 10MB

后端流程：
  1. 接收微信回调
  2. 下载文件到平台
  3. 调用 OCR + LLM 解析
  4. 返回小程序确认页
```

## 5. 子模块 4：虚拟号中继

### 5.1 设计

```
买家点击"联系卖家" → 虚拟号呼叫

电话流程：
  买家拨：950-XX-XX-XX-1234（平台虚拟号）
  平台中继：转接到卖家真实号码
  接通后：双方正常通话
  挂断后：
    - 通话记录留痕
    - 时长记录
    - AI 通话摘要（含合规过滤）
    - 同步到买家"我的供应商"+ 卖家 CRM
```

### 5.2 价值

| 价值 | 说明 |
|---|---|
| 保护隐私 | 双方不暴露真实号码 |
| 留痕合规 | 通话录音 + 关键词审核 |
| 数据沉淀 | 通话时长、AI 摘要 |
| 防脱媒 | 联系前 N 次必走平台 |
| 监管合规 | 涉黄涉赌涉骗即时屏蔽 |

### 5.3 限制规则

```
卖家联系次数限制：
  对同一买家：24h 内 ≤ 5 次（防骚扰）
  超限：买家有权举报，卖家信用扣分

通话频次限制：
  全平台单卖家 24h 通话 ≤ 50 次
  超限触发风控审查
```

### 5.4 技术对接

- **首选**：阿里云通信 / 腾讯云通信
- **备选**：容联七陌 / 网易七鱼
- **成本**：约 ¥0.3-0.5/分钟通话费

## 6. 子模块 5：企微群运营 SCRM

### 6.1 背景

货袋子有 2000 个老客户企微群（用户已有资产）。需要工具化运营。

### 6.2 SCRM 功能

```
群管理：
  - 群分级（S/A/B/C 自动打标）
  - 群健康度监控
  - 群成员标签（来源/角色/活跃度）

内容运营：
  - 定时群发（早 8 点行情等）
  - 群发权限分级
  - 内容审核
  - 群发 ROI 监控

询价转化：
  - 群内自然询价 AI 识别
  - 一键引导到平台
  - 转化率追踪
```

### 6.3 集成第三方 SCRM

```
平台可对接（但不强依赖）：
  - 企微官方 API
  - 微伴助手
  - 微盛 SCRM
  - 自研轻量化方案
```

## 9. 关键决策

### 9.1 不做独立 App（或非首选）

**理由**：
- 钢贸老板装 App 的意愿低
- 小程序 + 企微 已足够
- 减少开发成本
- 独立 App 可后期补做（V3）

### 9.2 微信支付仅用于"对私付费"

- SaaS/订阅可用微信支付（个人付）
- 大客户合同走对公转账
- 永远不碰交易资金

### 9.3 不做"打通微信好友圈"

- 不读取用户微信好友
- 不在微信里做病毒裂变
- 合规优先
