### 1.3 关键技术决策

#### A. AI 服务选型

| 能力 | 首选 | 备选 | 月成本预估（M3） |
|---|---|---|---|
| LLM | 通义千问 Max | GPT-4 Turbo / 文心一言 | ¥5000-15000 |
| OCR | 腾讯通用 OCR | 阿里 OCR / 百度 OCR | ¥1500-3000 |
| 表格 OCR | 腾讯表格 OCR | PaddleOCR（开源兜底） | ¥500 |
| 语音识别 | 讯飞 / 阿里 | 自研 | ¥800 |
| 推荐 | 自研（规则+协同过滤） | - | - |

#### B. 虚拟号

- 阿里云通信 / 腾讯云通信
- 通话费约 ¥0.3-0.5/分钟
- M3 预估月成本 ¥3000-5000

#### C. 即时通讯

- M1：自研轻量 IM（基于 WebSocket）
- V2：腾讯云通讯（专业 IM 服务，含视频/语音）

### 1.4 部署架构

```
生产环境（阿里云华北 2）：
  - K8s 集群（业务服务）
  - RDS 主从（MySQL）
  - Redis Cluster
  - ES 集群
  - OSS（文件）
  - SLB（负载均衡）

灾备：
  - 跨可用区部署
  - 每日全量备份 + 每小时增量
  - RTO ≤ 4h, RPO ≤ 1h

CDN：
  - 静态资源全国 CDN
  - 视频/图片接入 CDN
```

### 1.5 性能要求

| 派单 + 推送 15 家 | < 3s | < 10s | 20 |
| 聚合看板加载 | < 1s | < 2s | 200 |
| 搜索（卖家/资源） | < 500ms | < 1s | 100 |
| IM 消息发送 | < 200ms | < 500ms | 1000 |
| 行情查询 | < 200ms | < 500ms | 500 |

### 1.6 安全合规

- HTTPS 全站强制
- 数据传输 TLS 1.3
- 数据存储 AES-256 加密（敏感字段）
- 身份证号、银行账号 hash 化存储
- 通过《个人信息保护法》合规审查
- 通过《数据安全法》合规审查
- ICP 备案
- 增值电信业务许可
- 第三方安全审计（每年）

## 四、关键风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| AI 准确率不达预期 | 中 | 规则引擎兜底；钢贸术语词典持续迭代 |
| 微信封禁机器人 | 中 | 用企微开放 API（合规）；不诱导分享 |
| 虚拟号成本超预算 | 低 | 多供应商竞标；高频用户独立计费 |
| 数据库读写性能瓶颈 | 低 | 读写分离 + 分库分表（预留） |
| 高并发派单延迟 | 中 | 异步派单 + Kafka 削峰 |
| 数据安全事件 | 低 | 渗透测试 + 每年第三方审计 |

## 五、灰度策略

```
所有重大功能上线遵循"漏斗式灰度"：

Step 1: 内测（公司员工 + 种子卖家 30 家）
   ↓ 1 周
Step 2: 唐山小灰度（100 卖家 + 50 买家）
   ↓ 1 周
Step 3: 唐山+天津灰度（500 卖家 + 200 买家）
   ↓ 2 周
Step 4: 环渤海+山东（全部）
   ↓ 评估
Step 5: 全网

任一阶段出现严重问题 → 立即回滚 + 复盘
```

## 六、应急回滚

```
功能开关（Feature Flag）：
  所有 P0/P1 功能均通过功能开关控制
  紧急回滚：< 5 分钟

数据回滚：
  关键操作幂等设计
  数据库每小时增量备份
  误删/误改可在 1 小时内恢复

风控应急：
  误伤率 > 10% → 立即下线规则
  漏判率 > 10% → 立即加严规则
  CEO + 风控总监 24h on-call
```

## 八、迭代后的版本管理

- **每周一**：阻力清单 Weekly + 当前 sprint review
- **每两周**：sprint 发版（含小功能 + bug 修复）
- **每月**：大版本评审（重大功能）
- **每季度**：PRD 全面 review + 卖家委员会评议
- **每半年**：技术架构评审
