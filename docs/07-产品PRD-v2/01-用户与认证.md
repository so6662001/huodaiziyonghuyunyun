# M1：用户与认证模块

## 1. 模块目标

- 30 秒完成注册，不阻塞首次价值体验
- 营业执照 OCR 自动识别，零手动填字段
- 微信生态原生登录，避免账号密码
- 双重身份（买家+卖家）支持，避免重复注册

## 2. 用户故事

```
US-1.1（注册）
作为一个新到访的钢贸采购员，
我希望 30 秒内完成注册并发出第一个需求，
以便快速判断这个平台是否对我有用。

US-1.2（双重身份）
作为一个二级钢贸商，
我既要发资源（当卖家）也要找货（当买家），
希望一个账号就能两种身份切换，
不用注册两次。

US-1.3（企业账户）
作为一个钢结构厂的采购经理，
我希望我们公司的采购档案统一管理，
但又允许我个人保留独立的"成长账户"（可带走）。
```

## 3. 关键设计决策

### 3.1 双层账号模型

```
个人账户（User）
  ├─ 一个手机号 + 一个微信
  ├─ 个人成长账户数据
  └─ 可关联多个企业账户

企业账户（Company）
  ├─ 一个营业执照（唯一）
  ├─ 公司维度的采购历史/项目档案
  └─ 可关联多个个人账户（含权限分级）
```

**关键**：采购员换工作后，**个人数据带走，企业数据留下**。

### 3.2 身份模型

```
默认双重身份（不强制选择买家/卖家）
  系统根据行为自动识别主用途：
  - 30 天内发需求 > 0 → 主买家
  - 30 天内报价 > 0 → 主卖家
  - 两者都有 → 双重身份

UI 上提供"切换视角"按钮（如同微信的角色切换）
```

### 3.3 三层认证体系

| 级别 | 要求 | 权限 |
|---|---|---|
| L1 游客 | 无 | 浏览公开内容（行情/部分资源） |
| L2 注册 | 手机号验证 | 可发需求（试水池）/可见报价但不可联系 |
| L3 认证 | 营业执照 + 法人 OCR 核验 | 进入标准池 / 可联系卖家 / 可发悬赏 |
| L4 高级认证 | 视频验厂 + 实地核查 | 卖家进入优质池 / 买家进入大客户通道 |

## 5. 数据模型

### 5.1 User（个人账户）

```typescript
interface User {
  user_id: string;              // PK
  phone: string;                 // 唯一索引
  wechat_open_id: string;        // 微信 openid
  wechat_union_id: string;       // 微信 unionid（用于跨小程序识别）
  name: string;
  avatar: string;
  id_card_hash: string;          // 身份证号 hash（合规）
  primary_role: 'buyer'|'seller'|'both';
  current_view: 'buyer'|'seller';
  growth_account: GrowthAccount; // 个人成长账户
  created_at: timestamp;
  last_active_at: timestamp;
}
```

### 5.2 Company（企业账户）

```typescript
interface Company {
  company_id: string;
  business_license_no: string;   // 营业执照统一社会信用代码（唯一）
  name: string;
  legal_person: string;
  legal_person_id_hash: string;
  registered_address: string;
  operating_address: string;
  industry: string;              // 钢结构/机械加工/钢贸 等
  scale: 'small'|'medium'|'large';
  ocr_data: object;              // OCR 原始识别结果
  manual_filled: boolean;
  verified: boolean;
  verification_level: 'L1'|'L2'|'L3'|'L4';
  verified_at: timestamp;
  created_at: timestamp;
}
```

### 5.3 UserCompanyMapping（个人-企业关系）

```typescript
interface UserCompanyMapping {
  id: string;
  user_id: string;
  company_id: string;
  role: 'owner'|'admin'|'purchaser'|'salesperson';
  permissions: string[];         // 细粒度权限
  joined_at: timestamp;
  removed_at: timestamp | null;
}
```

### 5.4 GrowthAccount（个人成长账户）

```typescript
interface GrowthAccount {
  total_demands_published: number;
  total_deals_closed: number;
  total_savings: number;          // 累计省钱（vs 市场价）
```

## 7. 状态机

### 7.1 营业执照认证状态

```
未上传 → 已上传待核验 → 自动核验通过/失败
                              ↓                ↓
                          人工复核          通知补正
                              ↓
                       通过 / 拒绝
```

### 7.2 用户身份切换

```
新注册（无身份倾向）
  └─→ 首次发需求 → 主身份=买家
  └─→ 首次报价 → 主身份=卖家
  └─→ 两者都有 → 双重身份

当前视角（视图切换）：
  buyer ⇄ seller
  （随时切换，不影响主身份）
```

## 8. 反作弊规则（与 M11 联动）

| 规则 ID | 触发 | 处置 |
|---|---|---|
| R001 | 同设备 24h 内注册 ≥3 账号 | 人工审核，48h 设备拉黑 |
| R002 | 营业执照唯一性 | 拒绝重复注册，提示"已存在" |
| R003 | 信息完整度 < 50 | 限制只能浏览 |
| R004 | 同 IP 段 10 分钟内 ≥3 个注册 | 人工审核 |
| R005 | 黑名单关联 | 直接拒绝 |

## 9. 关键 UX 决策

### 9.1 微信一键登录优先

- 钢贸老板 70% 在微信里
- 微信登录 = 一次点击 + 自动获取 unionid → 后续企微集成无缝
- 手机号登录作为备选

### 9.2 OCR 不强制，但有强引导

- 上传营业执照 = 进入标准池（试水池太冷）
- 不上传 = 试水池（卖家少、报价少）
- 引导但不强制，给用户一定空间

### 9.3 双重身份默认开启

- 二级钢贸商既是买家也是卖家
- 不要让他在两个 App 里切换
- 一个账户，两种视图

### 9.4 企业账户支持"个人独立带走"

- 数据归属 = 企业数据（项目档案、采购历史）+ 个人数据（成长账户）
- 个人离职后，企业数据留下，个人成长账户可带走
- 这是采购员愿意主动用平台的核心激励

## 10. 埋点

| 事件 | 触发 | 关键字段 |
|---|---|---|
| user_register_start | 进入注册页 | source（wechat/sms/h5） |
| user_register_success | 注册成功 | user_id, source, time_cost |
| company_ocr_upload | 上传营业执照 | image_quality |
| company_ocr_result | OCR 完成 | success, fields_extracted |
| company_verified | 认证通过 | level |
| view_switch | 切换买卖家视角 | from_role, to_role |

## 11. 边界与异常

| 场景 | 处理 |
|---|---|
| OCR 识别失败 | 降级为手动填写，标黄提醒 |
| 营业执照已被注册 | 提示"该企业已注册"，引导申请加入 |
| 同手机号两个微信 | 第二个微信绑定时提示冲突 |
| 微信解绑后重新绑定 | 允许，但需短信二次验证 |
| 法人变更（OCR 重新识别） | 进入人工复核，原认证状态保留 30 天 |

## 12. 验收标准

| 指标 | 目标 |
|---|---|
| 注册-认证完成率 | ≥ 60% |
| 注册耗时（中位） | < 60 秒 |
| OCR 识别准确率 | ≥ 90% |
| 微信登录成功率 | ≥ 95% |
| 营业执照重复注册拦截率 | 100% |
