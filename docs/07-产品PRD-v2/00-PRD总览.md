## 1. 产品定位

### 1.1 一句话

> **货袋子是一个长在微信里的钢贸 AI 采购助手。**

不是"另一个找钢网"，不是"撮合 GMV 平台"——是中小钢贸采购员的工作助手 + 卖家的渠道扩展工具。

### 1.2 旧定位 vs 新定位

| 旧定位（找钢网模式） | 新定位 |
|------|------|
| B2B 撮合平台 | AI 采购助手 |
| 替代主供应商 | 补充渠道（应急/特殊/小单/试探） |
| 比价工具 | 关系培育器 + 工作交付物生成器 |
| 卖家越内卷越赚 | 卖家越赚平台越赚 |
| 围着 GMV 转 | 围着 take rate + NPS 转 |

### 1.3 五大产品红线（永不触碰）

1. ❌ **永不做自营货权**——平台只做信息+撮合
2. ❌ **永不做仓储/加工/物流自建**——只做信息聚合
3. ❌ **永不抽交易佣金**——靠 SaaS/流量费/数据/金融分润赚钱
4. ❌ **永不做交易补贴战**——只在关键引流场景小额补贴（如试单）
5. ❌ **永不向买家个人收费**——买家端 100% 免费

## 2. 用户与场景

### 2.1 用户角色

| 角色 | 描述 | 占比 |
|---|---|---|
| **A 类买家：终端制造业采购** | 钢结构厂、机械加工厂、家电厂、集装箱厂 的采购经理或老板 | 60%（**主战场**） |
| **B 类买家：二级钢贸/加工配送** | 剪切、开平、纵剪小厂，**既是买家也是卖家** | 25% |
| **C 类买家：工程项目方** | 建筑、市政工程的项目经理 | 15%（后期） |
| **S 类卖家：贸易商** | 钢贸商家（民营、非国营） | 主力 |
| **S2 类卖家：钢厂直营** | 钢厂自营销售部门 | 头部 |
| **采购员个人** | 公司内的执行者（关键产品决策对象） | 跨角色 |

### 2.2 三大核心场景（货袋子重新定位的真实战场）

| 场景 | 描述 | 占比 | 平台契合度 |
|---|---|---|---|
| **A. 应急供货** | "老供应商交不出货怎么办" | 20% | ⭐⭐⭐⭐⭐ |
| **B. 特殊规格** | "我老供应商没这个货" | 15% | ⭐⭐⭐⭐⭐ |
| **C. 小额补充** | "零散小单老供应商不愿做" | 10% | ⭐⭐⭐⭐ |
| 摸底市场价 | 已知行情，给老供应商谈判筹码 | 30% | ⭐⭐（用行情订阅产品转化） |
| 备用渠道储备 | 储备型，长期价值 | 8% | ⭐⭐⭐ |
| 真采购（新公司/换供应商） | 5%+2%=7% | ⭐⭐⭐⭐⭐ |

**让出场景**：大单主供应、长期合约、大型工程招标。

### 2.3 北极星指标

**N1：月有效撮合需求数**
- 定义：买家发起 + 卖家响应 + 双方互留联系方式或下单
- 目标：M3 ≥ 3000 / M6 ≥ 12000 / M12 ≥ 60000

**N2：单需求 30 分钟有效报价数 ≥ 3 的占比 ≥ 70%**

**N3：买家发起 → 主动联系卖家的转化率 ≥ 60%**

**N4：自报成交率 ≥ 15%**

### 2.4 反指标（禁止追逐的虚荣指标）

- ❌ GMV（除非用于宏观对标，不作为内部 KPI）
- ❌ 注册用户数（买家可能完全沉默）
- ❌ DAU（B2B 不是日活生意）

## 4. 整体数据模型（顶层视图）

详细字段见各模块文档。这里给出实体关系总览：

```
User ─┬─→ Account (Buyer / Seller)
      ├─→ CreditScore (双边)
      ├─→ Wallet (积分/现金/激励金)
      └─→ Preference (接单偏好/通知偏好)

PurchaseSession（采购会话，核心实体）
  ├─→ DemandCard (动态需求卡片，可被多次编辑)
  ├─→ ProcurementList (采购清单，可包含多 DemandCard)
  ├─→ Dispatches (派单记录，1对多)
  ├─→ Quotes (报价，含 6 维方案 + 阶梯定价)
  ├─→ Contacts (联系记录，IM/虚拟号)
  ├─→ Deals (成交回填)
  ├─→ Negotiations (议价记录)
  └─→ Events (操作时间线，含 AI 识变事件)

Project (项目档案)
  └─→ PurchaseSessions (1对多，归档复用)

WechatBinding (企微/微信绑定)
  └─→ User

Transaction (交易/支付/分润)
  ├─→ Membership / TrafficFee / SaaSContract / DataSubscription
  └─→ User

RiskEvent (风控事件)
  ├─→ Rule (规则 ID)
  ├─→ User
  └─→ Disposition (处置动作)
```

## 5. 关键设计原则（贯穿所有模块）

### 5.1 用户体验原则

1. **买家端：30 秒发需求**（首次）/ **3 秒发需求**（复用）
2. **卖家端：3 秒响应需求变更**
3. **30 秒发清单**（拍照/Excel/PDF/微信转发）
4. **比微信省事**：所有"重复的、模糊的、低效的"操作被结构化代替

### 5.2 反卖家反弹原则

1. **盲价匹配**：买家只看到 Top 3 综合最优，不是全网最低
2. **6 维报价**：单价 + 含运 + 账期 + 交货 + 加工 + 检测
3. **区域保护**：默认本地匹配，跨区需买家明确请求
4. **卖家选择权**：卖家可设置接单偏好，不被强制应付询价党
5. **价格底线**：低于市场价 8% 的报价默认隐藏（防恶性低报）

### 5.3 买家友好原则

1. **零付费门槛**：所有买家核心功能 100% 免费
2. **算法分级**：买家无感分级（试水/标准/优质池）
3. **行为门槛**：用"完善资料/详细字段"代替"付费"
4. **试单激励**：首次成交平台垫付 ¥200-500
5. **不强制断微信**：核心功能可在微信里完成

### 5.4 数据沉淀原则

1. **任何动作都留痕**：用于审计/合规/AI 训练/CRM
2. **数据所有权归用户**：可导出、可迁移
3. **采购员个人成长账户**：数据可跨公司带走
4. **项目档案永久保存**

## 6. 验收标准（PRD 整体验收）

| 类别 | 指标 | 目标 |
|---|---|---|
| **核心体验** | 发需求中位耗时 | < 60 秒 |
|  | 复用上次需求耗时 | < 3 秒 |
|  | 需求变更耗时 | < 10 秒 |
|  | 清单上传成功率 | ≥ 80% |
| **业务转化** | 报价 → 联系率 | ≥ 40% |
|  | 联系 → 试单率 | ≥ 15% |
|  | 试单 → 复购率 | ≥ 60% |

|  | 变更后卖家退出率 | < 15% |
| **微信集成** | 微信端使用率 | ≥ 50% |
| **AI 能力** | OCR+LLM 解析准确率 | ≥ 90% |

- **PRD 版本管理**：每个 PR 关联 PRD 段落引用
