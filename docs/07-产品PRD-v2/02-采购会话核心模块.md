# M2：采购会话核心模块 ⭐

> **本模块是货袋子产品的灵魂**。彻底替代旧 PRD v1 中的"需求-报价"离散原子模型。

## 0. 核心场景设定（v2.1 修正）

> ⚠️ **关键设定**：钢贸采购 80%+ 询价是**多规格清单**（5-30 行不等），单条规格只是少数特例。
> 因此本模块的所有交互**默认多规格**，单条只是 N=1 的退化情况。

```
真实场景示例（华建工集团一个项目的询价单）：

┌─────────────────────────────────────────────────────┐
│ ① 热轧 Q235B 5.5×1500×C   50 吨  → 天津  ≤¥3950   │
│ ② 热轧 Q235B 4.0×1500×C   30 吨  → 天津  ≤¥4000   │
│ ③ 螺纹 HRB400E Φ18×12m   100 吨  → 唐山  ≤¥4100   │
│ ④ 螺纹 HRB400E Φ20×12m    80 吨  → 唐山  ≤¥4150   │
│ ⑤ 镀锌 SGCC 0.5×1200×C    30 吨  → 天津           │
│ ⑥ 镀锌 SGCC 0.6×1250×C    20 吨  → 天津           │
│ ⑦ H 型钢 HW200×200         5 吨  → 唐山           │
│ ⑧ 不锈钢 304 1.0×1219×C    5 吨  → 天津           │
└─────────────────────────────────────────────────────┘

特征：
- 8 条规格、3 个品类、2 个到货地
- 总量 320 吨、预算约 ¥1.3M
- 来自同一个项目，必须整体询价才有议价空间
- 卖家可能只能供其中 3-5 条
```

## 1. 模块目标

把真实采购的**连续对话流 + 多规格清单**做成产品的一等公民：
- **2 分钟发布 8 条规格**（vs 线下 4-6 小时打电话）
- 3 秒发变更
- 多卖家×多规格并行报价
- AI 自动识变 + 自动给出最优组合方案
- 按行独立成交（不需要"全成或不成"）
- 历史会话永久沉淀

## 3. 核心设计

### 3.1 旧模型 vs 新模型

**旧模型（找钢网/初版 PRD v1）**：

```
买家发需求 → 卖家报价 → 买家选 → 联系 → 成交
   ↑__________________|
   每次变更都要重来
```

**新模型（采购会话）**：

```
买家发起"采购会话"
  ↓
系统生成动态需求卡片（DemandCard）
  ↓
N 个卖家通过派单加入会话
  ↓
多方实时对话 + 卡片动态变更 + 报价并行
  ↓
最终成交（一家或多家组合）
```

### 3.2 "采购会话"实体

```
PurchaseSession
  ├─ 1 个 DemandCard（动态需求卡片，可被无限次编辑）
  ├─ N 个 SellerParticipation（参与的卖家）
  ├─ N 条 ConversationStream（每个卖家一条对话流，并行）
  ├─ M 个 Quote（报价，与卡片版本绑定）
  ├─ K 个 Negotiation（议价记录）
  ├─ J 个 ContactRecord（IM/电话/虚拟号记录）
  ├─ 1 个 SessionAggregator（买家聚合看板）
  ├─ 1 个 SessionTimeline（操作时间线，含 AI 识变事件）
  └─ 0/1 个 Deal（成交回填）
```

### 5.2 DemandCard（动态需求卡片 - 多规格）⭐ v2.1 重要修正

> **关键变更**：需求卡片**必须支持多条规格**（`items` 数组）。
> 钢贸 80%+ 询价为多规格清单，单条规格只是 `items.length === 1` 的退化情况。

```typescript
interface DemandCard {
  card_id: string;
  session_id: string;
  version: number;                // 版本号，每次变更+1
  is_current: boolean;

  // ⭐ 核心：多条规格明细数组
  items: DemandItem[];            // 1-100 行规格

  // 整单全局信息（每行可覆盖）
  default_delivery_city?: string;     // 默认到货城市
  default_delivery_district?: string; // 默认到货区/县
  default_delivery_date_range?: { start, end };
  default_payment_terms?: 'cash'|'3d'|'7d'|'30d';
  default_required_invoice_type?: 'normal'|'special';

  // 整单备注
  note?: string;

  // 整单策略
  split_strategy: 'auto' | 'bundle' | 'manual';
  // - auto:   智能拆单（按品类+区域），可分单成交
  // - bundle: 整单打包，仅接受全部能供的卖家
  // - manual: 手动指定哪几行打包给同家

  // 变更追踪
  changed_fields: ChangeRef[];    // 本次变更的字段（含行号）
  changed_by: 'buyer'|'ai_assist';
  change_reason?: string;
  created_at: timestamp;
}

interface DemandItem {
  item_no: number;                 // 行号（1-N）
  client_temp_id?: string;         // 客户端临时 ID（用于幂等）

  // 商品规格（必填）
  product_category: string;       // 热轧卷板/螺纹/H 型钢/...
  material_grade: string;         // Q235B/HRB400E/304/...
  spec: string;                   // 5.5×1500×C / Φ18×12m / HW200×200
  quantity: decimal;              // 数量
  quantity_unit: 'ton'|'kg'|'piece'|'meter';

  // 交付（可不填，回退到 default_*）
  delivery_city?: string;
  delivery_district?: string;
  delivery_date_range?: { start, end };

  // 价格期望（可不填，由 AI 估）
  target_price_max?: decimal;     // 目标价上限
  price_unit?: 'per_ton'|'per_piece';

  // 质量
  required_quality_certificate?: boolean;
  required_processing?: string;   // 探伤/定尺/包装

  // 行级备注
  note?: string;

  // 行级状态（运行时计算，非存储）
  status?: 'pending' | 'dispatching' | 'quoted' | 'locked' | 'deal' | 'no_supply';
  matched_quote_count?: number;
}

interface ChangeRef {
  item_no?: number;               // 如果是行级变更，记录行号；null 则是整单变更
  field: string;                  // 字段路径，如 'items[2].quantity'
  old_value: any;
  new_value: any;
}
```

#### 多规格设计要点

1. **行号稳定**：用户增删行后，已有行的 `item_no` 不变（新行追加最大号）
2. **行级变更**：AI 识变时必须识别"哪一行"（如"3 号规格加 10 吨"）
3. **全局 + 行级覆盖**：到货地、交期、账期可在整单设默认值，单行可覆盖
4. **拆单策略**：用户可选自动 / 打包 / 手动，影响派单与成交方式
5. **行级独立成交**：每行可独立锁价，部分成交不阻塞其他行
6. **行级状态机**：每行有独立状态（派单中/已报价/已锁定/已成交/无供应）

## 7. 核心业务流程

### 7.1 创建会话主流程

```
1. 买家点击"发需求" → 进入极简发需求页
2. 填写品名/材质/规格/数量/到货地（30 秒内）
3. POST /purchase-sessions
   → 后端创建 Session + 创建 v1 DemandCard
4. 触发 M5 智能匹配
   → 系统按规则推送给 N 个卖家
   → 创建 N 个 SellerParticipation（待接单）
5. 卖家收到推送（App/SMS/企微）
   → 卖家接单 → SellerParticipation 状态 = engaged
6. 卖家报价 → 创建 Quote（关联当前 card_version）
7. 买家在聚合看板看到所有报价
8. 买家选择联系 → 创建 ConversationStream
9. 双方对话 → 创建 Message
```

### 7.2 需求变更流程（核心创新）

```
方式 A：手动编辑
1. 买家点击需求卡片"编辑"
2. 弹出表单，修改字段
3. POST /sessions/{id}/cards（携带变更字段）
4. 后端：
   a. 当前 card.is_current = false
   b. 创建新版本 card.is_current = true
   c. 触发卡片变更通知给所有 engaged 卖家
5. 卖家收到通知
   → "买家把数量从 50 改为 80，您的报价是否调整？"
6. 卖家一键选择：维持/调整/退出
7. 时间线记录该事件

方式 B：AI 识变
1. 买家在 IM 输入"要不改成 80 吨吧"
2. 前端 → POST /ai/detect-intent
3. AI 服务返回：
   { intent_type: 'change_quantity',
     extracted_fields: { quantity_ton: 80 },
     confidence: 0.92 }
4. 前端展示确认条：[是，更新][否，继续聊]
5. 用户点"是" → 转方式 A 流程从步骤 3 开始
```

### 7.3 卡片变更同步策略

```
变更发生时，对每个 engaged 卖家：

字段级响应映射：
  quantity ↑      → 推送：是否设阶梯价？
  quantity ↓      → 推送：维持单价？
  spec 改         → 推送：同价/±N 元/退出
  delivery 变急   → 推送：加急费？
  payment 变长    → 推送：账期溢价？

推送通道：
  App push（即时）
  企微机器人（实时）
  短信（30 秒内未读补发）

响应有效期：60 分钟（默认）
未响应：维持原报价，但标记"未响应变更"
```

### 7.4 变更次数限制

```
免费变更次数：5 次/会话
6-10 次：每次自动给 engaged 卖家 ¥3 积分补偿
>10 次：标记买家为"反复变更"，提示卖家
  + 后续变更进入降权派单
```

## 8. AI 识变设计

### 8.1 LLM 选型

- **首选**：通义千问 / GPT-4 Turbo / 文心一言
- **本地化**：可选部署 Qwen 32B（高频场景降低成本）
- **降级方案**：规则引擎（关键字+正则）

### 8.2 Prompt 工程

```
系统提示：你是一个钢贸采购助手，需要从买家和卖家的对话中识别需求变更意图。

任务：分析以下消息，判断是否包含需求变更，若有则提取变更字段。

当前需求卡片：
  品名：{product}
  材质：{material}
  规格：{spec}
  数量：{quantity} 吨
  到货：{delivery_city}
  交期：{delivery_date}
  账期：{payment}

最新消息：{message}

输出 JSON：
{
  "has_intent": true/false,
  "intent_type": "change_quantity"|"change_spec"|...|null,
  "extracted_fields": {...},
  "confidence": 0.0-1.0,
  "natural_summary": "买家把数量改为 80 吨"
}

特别注意：
- 钢贸行话："螺18"=螺纹 ¢18mm；"30T"=30 吨；"H50T"=工字钢..
- 模糊表达："要不"、"能不能"应识别为询问而非确认
- 数量范围："50-80 吨"应识别为模糊询价
```

### 8.3 准确率与回退

| 置信度 | 处置 |
|---|---|
| ≥ 0.85 | 直接展示确认条 |
| 0.6-0.85 | 展示确认条 + 高亮提示"AI 不确定" |
| < 0.6 | 不打扰用户，仅后台记录 |

错误时用户可"撤销 AI 识别"（48 小时内）。

### 8.4 数据沉淀

```
每次 AI 识变后：
  - 记录原始消息
  - 记录 LLM 输出
  - 记录用户是否确认
  - 用户拒绝识别 → 标记为负样本
  - 月度回训 → 提升准确率

成本控制：
  - 单次 LLM 调用 < ¥0.01
  - 月预算上限 < ¥5000（M3 时）
```

   ↓        ↓         ↓          ↓           ↓
 cancelled cancelled cancelled cancelled  closed

              ↓        ↓        ↓

                            ↓

## 12. 异常处理

| 场景 | 处理 |
|---|---|
| 24h 内 0 报价 | 平台运营介入扩匹配 + 通知买家"系统正在为您扩大范围" |
| 卖家变更未响应（>1h） | 维持原报价，标记"未响应"，影响后续派单权重 |
| AI 识变错误（用户撤销） | 撤销卡片变更 + 记录负样本 |
| 变更次数 > 10 | 提示买家"反复变更可能影响卖家积极性" |
| 会话超时（72h 无活动） | 自动归档，可手动复活 |
| 卡片版本冲突（并发编辑） | 后写入获胜，给前者发"变更被覆盖"通知 |
