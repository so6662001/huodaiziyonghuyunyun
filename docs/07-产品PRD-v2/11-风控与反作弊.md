# M11：风控与反作弊

> 完整反作弊规则引擎详见 `docs/03-扩展交付物/03-3-反作弊规则引擎.md`。本文档为产品 PRD 视角的对接。

## 1. 模块目标

- 36 条反作弊规则覆盖 7 大风险维度
- 区域保护制（防外地低价冲击）
- 价格底线保护（防恶性低报）
- 区域风险监控（卖家联盟早期预警）
- 双向信用 + 申诉机制

## 2. 风险维度

| 维度 | 风险点 | 规则数 | 主要影响模块 |
|---|---|---|---|
| 注册环节 | 假账号、批量注册 | R001-R005 | M1 |
| 反向邀请 | 自邀自、薅羊毛 | R006-R012 | M7 |
| 发需求 | 询价党、探价 | R013-R018 | M2 |
| 报价 | 同质化、串价 | R019-R023 | M4 |
| 联系沟通 | 跳单、骚扰 | R024-R027 | M9 |
| 成交回填 | 虚假成交 | R028-R031 | M2 |
| 流量费 | 套现、刷线索 | R032-R036 | M10 |

## 3. 引擎架构

```
事件源（注册/发需求/报价/邀请/支付/通话）
    ↓
特征采集层（设备指纹/IP/营业执照/行为序列）
    ↓
规则引擎层（36 条规则同时跑）
    ↓
决策层（通过/限流/人工审核/拦截/封号）
    ↓
处置层（执行+通知+申诉入口）
    ↓
反馈学习层（人工复核结果回流到规则迭代）
```

## 4. 处置分级

| 等级 | 处置 | 触发示例 |
|---|---|---|
| L0 | 提示+教育 | R013 第一次询价党 |
| L1 | 限流（功能降级 24h） | R022 报价撤回过多 |
| L2 | 限制（暂停功能 7-30d） | R023 恶意低价 |
| L3 | 暂停（账号 72h） | R026 黑话灰产 |
| L4 | 封号（永久） | R005 黑名单 / 严重违规 |

## 5. 关键产品集成

### 5.1 区域保护制（M5 集成）

```
默认：本地匹配
跨区：买家明确请求 + 卖家可见"跨区"标识

监控：
  - 跨区成交占比 ≤ 10%
  - 区域内响应率突降 >20%/周 → 红色预警
```

### 5.2 价格底线（M4 集成）

```
报价 < 市场参考价 × 0.92 → 默认隐藏
报价 < 市场参考价 × 0.85 → 提示卖家"可能存在风险"
连续 3 次异常报价 → 进入限制池（72h 降权）
```

### 5.3 询价党管控（M2/M5 集成）

```
30 日发需求 ≥ 30 条 且 0 成交 → 标记"询价党"
  → 进入试水池
  → 卖家可选"不接询价池"
  → 月度发需求上限 30 条
```

### 5.4 同质化报价检测（M4 集成）

```
同一需求收到 N≥3 条报价，方差 < 0.5%
  → 怀疑串价
  → 人工抽查
  → 命中卖家加入"串价观察名单"
```

### 5.5 跳单识别（M9 集成）

```
信号采集：
  - IM 中出现微信号/电话号
  - 通话关键词识别（"加我微信"）
  - 双方 IM 突然停止但需求未关闭

跳单分 = 0.3×联系方式出现 + 0.3×停止平台沟通 + 0.4×需求未关闭

> 0.7 → 推送平台增值服务提醒 + 标记"疑似跳单"
注意：不强制阻断，只引导回归
```

## 6. 区域风险监控（致命预警）

详见 `docs/04-战略迭代/04-1-反卖家反弹方案.md` 机制 12。

### 6.1 监控信号

| 信号 | 阈值 | 处置 |
|---|---|---|
| 区域内卖家响应率突降 | 一周内 >20% | 黄色预警 |
| 卖家报价均价突然趋同（方差<1%） | 持续 3 天 | 红色预警 |
| 卖家退会员费请求集中 | 同区域一周 >5 家 | 红色预警 |
| 商会/协会出现负面舆情 | 任一次 | 紫色预警 |
| 卖家间私信"抵制货袋子" | 任一次 | 紫色预警 |
| 头部卖家停止登录 | >7 天 | 黄色预警 |

### 6.2 危机处理 SOP

```
T+0      监控系统报警
T+4h     运营负责人 + CEO 紧急会议
T+24h    重点卖家逐一电话沟通
T+48h    出整改方案
T+72h    召开卖家委员会临时会议
T+1w     回到正常运营
```

## 7. 申诉机制

```
所有 L1-L3 处置必须可申诉

申诉入口：App 内 + 客服热线
处理时效：24h 内出结论

申诉通过率监控：维持在 15-25%
  过低 → 误伤多
  过高 → 规则太松
```

## 9. 核心接口

```
# 风控
POST   /api/v1/risk/check                    实时风控校验（内部）
POST   /api/v1/risk/events                   记录风控事件
GET    /api/v1/risk/events/me                我的风控记录
POST   /api/v1/risk/appeals                  发起申诉

# 市场参考价
GET    /api/v1/market-references             查询参考价
POST   /api/v1/market-references/recompute   重算（内部定时）

# 区域风险监控
GET    /api/v1/admin/region-alerts            报警列表
POST   /api/v1/admin/region-alerts/{id}/resolve 标记解决

# 规则管理（仅内部 admin）
GET    /api/v1/admin/risk-rules               规则列表
PATCH  /api/v1/admin/risk-rules/{id}          调整规则
POST   /api/v1/admin/risk-rules/{id}/test     A/B 测试
```

## 11. 规则迭代节奏

```
每周：风控团队 review 误伤率/漏判率
每月：规则版本升级
每季度：与外部反作弊厂商对标
每半年：第三方安全审计
```

## 12. 合规

```
数据合规：
  - 通过《个人信息保护法》合规审查
  - 通过《数据安全法》合规审查
  - 用户数据可导出（GDPR/个保法）
  - 第三方安全审计

业务合规：
  - 不放贷、不做资金池
  - 不存储完整身份证号（hash 化）
  - IM 不留个人隐私信息
  - 通话录音征得双方同意
```
