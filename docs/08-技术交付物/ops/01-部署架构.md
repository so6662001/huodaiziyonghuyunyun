## 二、Kubernetes 集群规划

### 1. 集群规模（M3）

| 节点池 | 用途 | 数量 | 规格 |
|---|---|---|---|
| system | K8s 控制面 + 监控 | 3 | 8C16G |
| app-web | 业务应用 | 10 | 4C8G |
| app-ai | AI 服务（高内存） | 3 | 16C32G |
| app-batch | 定时任务/异步 | 3 | 4C8G |
| storage | 数据中间件 | 6 | 16C64G |

### 2. 命名空间

```yaml
namespaces:
  - prod-app          # 业务应用
  - prod-data         # 数据中间件（如自管）
  - prod-monitor      # Prometheus/Grafana
  - prod-logging      # ELK
  - prod-ingress      # 网关
  - staging           # 灰度环境
```

### 3. 资源配额

```yaml
# 每个 namespace 限制
apiVersion: v1
kind: ResourceQuota
metadata:
  name: prod-app-quota
spec:
  hard:
    requests.cpu: "100"
    requests.memory: 200Gi
    limits.cpu: "200"
    limits.memory: 400Gi
    persistentvolumeclaims: "20"
```

### 4. 高可用部署

每个业务服务：
- 至少 3 副本
- 跨可用区分布（podAntiAffinity）
- 滚动更新（maxSurge 25% + maxUnavailable 25%）
- 健康检查（livenessProbe + readinessProbe）
- 自动扩缩（HPA：CPU > 70% 或 QPS > 100/pod）

## 三、数据库部署

### 1. MySQL 主从

```
主库（Master）
  规格：32C64G + 1TB SSD
  位置：可用区 A

从库 1（Read Replica）
  规格：32C64G + 1TB SSD
  位置：可用区 B
  用途：业务读

从库 2（Backup Replica）
  规格：16C32G + 1TB SSD
  位置：可用区 C
  用途：备份 + 延迟恢复
  延迟：1 小时（防误操作）
```

### 2. 读写分离

```
应用层用 ProxySQL / ShardingSphere-Proxy
  写：发到 Master
  读：负载均衡到 Read Replicas

注意：
  - 强一致性读走 Master（如下单后立即查询）
  - 一般读走 Replica
```

### 3. 分库分表预留

```
M12+ 大表分库分表方案：

按 user_id hash：
  - messages（千万级）
  - session_events（千万级）
  - risk_events（千万级）
  - audit_logs（千万级）

按时间分区：
  - audit_logs（按月分区，6 月归档到 OSS）
  - messages（按月分区）

工具：ShardingSphere-JDBC
```

### 4. Redis 部署

```
Redis Cluster
  3 主 3 从
  每节点 8GB（总 48GB，业务用 16GB）
  跨可用区

使用：
  - 缓存（最大）
  - 分布式锁
  - 计数器
  - 限流令牌桶
  - 会话状态
```

### 5. Kafka 部署

```
3 节点集群
  规格：8C16G + 500GB SSD
  跨可用区

主题分区策略：
  - 高吞吐主题（消息、事件）：12 分区
  - 一般主题：6 分区
  - 副本因子：3

关键主题：
  - session.events
  - dispatch.requested
  - message.sent
  - risk.event
  - notification.send
```

## 四、网络架构

### 1. VPC 设计

```
生产 VPC（10.0.0.0/16）
  ├ 公网子网（10.0.1.0/24）
  │   - SLB
  │   - NAT 网关
  ├ 应用子网（10.0.10.0/24, 10.0.11.0/24, 10.0.12.0/24）
  │   - K8s 节点（跨 3 个可用区）
  ├ 数据子网（10.0.20.0/24, 10.0.21.0/24, 10.0.22.0/24）
  │   - MySQL/Redis/Kafka
  └ 管理子网（10.0.30.0/24）
      - 跳板机
      - 监控
```

### 2. 安全组规则

```
公网入站：
  - 80/443 仅允许 CDN/SLB
  - 其他全部拒绝

应用层：
  - 仅允许网关到业务服务
  - 服务间通过 K8s Service DNS

数据层：
  - 仅允许应用子网访问
  - 拒绝公网

管理：
  - SSH 仅允许跳板机
  - 跳板机用堡垒机审计
```

### 3. DNS

```
huodaizi.com
  ├ www         → CDN → SLB
  ├ api         → SLB → API 网关
  ├ admin       → 内网 SLB
  ├ static      → CDN → OSS
  └ webhook     → SLB → 公网网关
```

## 五、镜像与配置

### 1. 镜像规范

```
所有镜像基于 distroless 或 alpine
不允许 root 用户运行
镜像扫描后再推送（Trivy）

标签策略：
  - latest（不允许在生产用）
  - v2.0.0（语义版本）
  - sha-abc1234（提交 hash）

生产环境只能用 sha 或 vX.Y.Z 标签。
```

### 2. 配置管理

```
分级：
  1. 代码内（Spring config）：通用默认
  2. 配置中心（Nacos）：环境差异
  3. K8s Secret：敏感数据

敏感数据：
  - 数据库密码
  - 第三方 API Key
  - JWT Secret

定期轮换（每季度）。
```

## 六、域名与证书

```
SSL 证书：
  - 使用阿里云免费证书 / Let's Encrypt
  - 自动续期
  - HTTPS 强制跳转
  - HSTS 启用

TLS 版本：≥ 1.2（建议 1.3）
```

## 七、CDN 配置

```
缓存策略：
  - 静态资源（JS/CSS/图片）：1 年
  - API 响应：不缓存
  - 视频：1 年

跨域：
  - 严格白名单（不要 *）
  - 仅允许：huodaizi.com 及其子域

图片处理：
  - 通过 URL 参数自动压缩/裁剪
  - WebP 自动转换
  - 防盗链
```

## 八、灾备节点

```
主区：阿里云华北 2（北京）
副区：阿里云华东 1（杭州）

主备数据同步：
  - MySQL：异步复制（延迟 < 5s）
  - OSS：跨区域复制（异步）
  - 应用：双活就绪（V3 启用）

灾备切换：
  - DNS 切换（5 分钟生效）
  - 数据切换：手工触发（避免误切）
  - 演练：每年 2 次
```

## 九、容量预警

```
所有关键资源设置 3 级预警：

绿色：使用率 < 60%
黄色：60-75%（提前规划扩容）
红色：> 75%（立即扩容）

监控对象：
  - K8s 节点 CPU/内存
  - MySQL 容量/连接数
  - Redis 内存
  - Kafka 磁盘
  - ES 容量
  - OSS（自动扩展，仅监控成本）
```
