# 监控与告警

## 一、监控分层

```
Layer 1: 基础设施
  - K8s 集群、节点资源
  - 数据库、缓存、消息队列
  - 网络、CDN

Layer 2: 应用层
  - JVM/Go runtime 指标
  - API 延迟、错误率
  - 中间件连接池

Layer 3: 业务层
  - 北极星指标（月有效需求数等）
  - 转化漏斗
  - 收入指标

Layer 4: 用户体验
  - 真实用户监控（RUM）
  - 拨测
  - APM
```

## 二、Prometheus + Grafana

### 1. 关键指标（业务）

```promql
# 月有效需求数（北极星指标）
sum(increase(huodaizi_session_created_total[30d]))

# API QPS
sum(rate(http_request_total[1m])) by (path)

# API P95 延迟
histogram_quantile(0.95, sum(rate(http_request_duration_seconds_bucket[5m])) by (path, le))

# 错误率
sum(rate(http_request_total{status=~"5.."}[5m])) / sum(rate(http_request_total[5m]))

# AI 服务成本（实时）
sum(rate(ai_request_total[1h])) * 0.10  # 每次约 0.10 元

# 派单成功率
sum(rate(dispatch_success_total[5m])) / sum(rate(dispatch_attempt_total[5m]))

# 卖家响应率
sum(rate(dispatch_responded_total[5m])) / sum(rate(dispatch_total[5m]))
```

### 3. 告警规则

```yaml
groups:
  # 基础设施告警
  - name: infrastructure
    rules:
      - alert: NodeCPUHigh
        expr: 100 - (avg by (instance) (irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 80
        for: 10m
        severity: warning

      - alert: NodeMemoryHigh
        expr: (1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes) * 100 > 85
        for: 5m
        severity: warning

      - alert: DiskSpaceFull
        expr: (1 - node_filesystem_avail_bytes / node_filesystem_size_bytes) * 100 > 80
        for: 5m
        severity: warning

  # 数据库告警
  - name: database
    rules:
      - alert: MySQLConnectionsHigh
        expr: mysql_global_status_threads_connected / mysql_global_variables_max_connections > 0.8
        for: 5m
        severity: warning

      - alert: MySQLSlowQuery
        expr: rate(mysql_global_status_slow_queries[5m]) > 10
        for: 5m
        severity: warning

      - alert: MySQLReplicationLag
        expr: mysql_slave_status_seconds_behind_master > 5
        for: 3m
        severity: critical

      - alert: RedisMemoryHigh
        expr: redis_memory_used_bytes / redis_memory_max_bytes > 0.85
        for: 5m
        severity: warning

  # 应用告警
  - name: application
    rules:
      - alert: HighErrorRate
        expr: |
          sum(rate(http_request_total{status=~"5.."}[5m])) by (service) /
          sum(rate(http_request_total[5m])) by (service) > 0.01
        for: 5m
        severity: critical

      - alert: HighLatency
        expr: |
          histogram_quantile(0.95,
            sum(rate(http_request_duration_seconds_bucket[5m])) by (service, le)
          ) > 2
        for: 5m
        severity: warning

      - alert: ServiceDown
        expr: up == 0
        for: 1m
        severity: critical

  # 业务告警
  - name: business
    rules:
      - alert: DailySessionDropAnomaly
        expr: |
          sum(increase(huodaizi_session_created_total[1d])) /
          sum(increase(huodaizi_session_created_total[1d] offset 7d)) < 0.7
        for: 1h
        severity: warning

      - alert: PaymentFailureSpike
        expr: rate(payment_failed_total[5m]) > 0.05
        for: 5m
        severity: critical

      - alert: AIServiceFailure
        expr: rate(ai_request_failed_total[5m]) > 0.05
        for: 3m
        severity: critical

  # 区域风险（核心业务预警）
  - name: regional_risk
    rules:
      - alert: RegionalResponseRateDrop
        expr: |
          sum(rate(dispatch_responded_total[1h])) by (region) /
          sum(rate(dispatch_total[1h])) by (region) < 0.5
        for: 2h
        severity: critical
        labels:
          notify_ceo: true

      - alert: SellerMassChurn
        expr: |
          sum(increase(membership_cancelled_total[1d])) by (region) > 5
        for: 1d
        severity: critical
        labels:
          notify_ceo: true

      - alert: PriceVarianceCollusionSuspect
        expr: |
          quote_variance_by_session{session_quotes_count="3"} < 0.005
        for: 1h
        severity: warning

      - alert: ChamberOfCommerceNegativeBuzz
        expr: increase(forum_negative_buzz_total[1h]) > 0
        for: 0s
        severity: critical
        labels:
          notify_ceo: true
```

### 4. 告警通道

```yaml
# AlertManager 配置
receivers:
  - name: 'sre-team'
    webhook_configs:
      - url: 'https://oapi.dingtalk.com/...'    # 钉钉机器人

  - name: 'cto-pager'
    webhook_configs:
      - url: 'https://oapi.dingtalk.com/...'
    pagerduty_configs:
      - service_key: '...'                       # PagerDuty

  - name: 'ceo-emergency'
    webhook_configs:
      - url: 'https://oapi.dingtalk.com/...'
    email_configs:
      - to: 'ceo@huodaizi.com'

# 路由规则
route:
  group_by: ['alertname']
  group_wait: 10s
  group_interval: 5m
  repeat_interval: 1h
  receiver: 'sre-team'
  routes:
    - match:
        severity: critical
      receiver: 'cto-pager'
      repeat_interval: 30m
    - match:
        notify_ceo: true
      receiver: 'ceo-emergency'
      continue: true
```

## 三、日志（ELK）

### 1. 日志规范

```
所有日志使用 JSON 格式：

{
  "timestamp": "2026-05-23T14:32:00Z",
  "level": "INFO",
  "service": "session-service",
  "trace_id": "abc123",
  "span_id": "def456",
  "user_id": "u_xxx",
  "action": "create_session",
  "message": "...",
  "duration_ms": 123,
  "extra": {...}
}
```

### 2. 日志级别

| 级别 | 用途 | 保留时长 |
|---|---|---|
| ERROR | 错误（必须修复） | 6 个月 |
| WARN | 警告（关注） | 3 个月 |
| INFO | 业务操作 | 3 个月 |
| DEBUG | 调试（生产关闭） | 1 周 |

### 3. 关键日志

```
必须有日志的操作：
  - 所有写操作（创建/修改/删除）
  - 登录/退出
  - 权限校验失败
  - 风控规则触发
  - 第三方 API 调用
  - 异常错误
  - 慢操作（> 1s）
```

### 4. 日志查询

```
Kibana 模板查询：

# 查某用户的所有操作
service: * AND user_id: "u_xxx"

# 查某 trace 的全链路
trace_id: "abc123"

# 查 ERROR 级别
level: "ERROR"

# 查慢操作
duration_ms: > 1000
```

## 四、APM / 链路追踪

```
工具：Jaeger / SkyWalking / Apache SkyWalking

追踪范围：
  - 所有 HTTP 请求
  - 数据库调用
  - Redis 调用
  - Kafka 生产/消费
  - 第三方 API 调用

采样：
  生产：1% 采样（防成本爆炸）
  错误：100% 采样
```

## 五、错误监控（Sentry）

```
所有未捕获异常自动上报 Sentry

Sentry 项目分类：
  - api-service
  - mobile-app
  - miniprogram
  - admin-dashboard

告警规则：
  - 新错误立即通知开发
  - 高频错误（>10 次/小时）→ SRE
  - 关键功能错误（支付、登录） → 立即 CTO
```

## 六、真实用户监控（RUM）

```
前端埋点：
  - 页面加载时间
  - 首屏渲染
  - 用户路径
  - 设备/浏览器分布
  - 错误率（前端 JS error）

工具：阿里云 ARMS / 自研

关键指标：
  - LCP < 2.5s
  - FID < 100ms
  - CLS < 0.1
```

## 七、拨测

```
工具：阿里云监控 / 自建

拨测点：
  - 北京、上海、广州、成都、武汉
  - 每 5 分钟拨测

拨测项：
  - 首页加载
  - 登录 API
  - 关键 API 端点

告警：
  - 任一拨测点失败 > 3 次 → 警告
  - 多个拨测点失败 → 严重
```

## 八、值班 SOP

```
P0 故障（5 分钟内 ack）：
  1. 立即拉群（CTO + SRE + 相关业务负责人）
  2. 启动故障作战流程
  3. 优先恢复服务（先恢复后定位）

P1 故障（15 分钟内 ack）：
  1. SRE 接手处理
  2. 1h 内同步进展

P2 故障（1h 内 ack）：
  1. 工作时间内处理

事后复盘：
  P0/P1 故障必须 24h 内出复盘报告
  包含：根因分析、时间线、改进措施
```

## 九、监控成本控制

```
监控本身有成本，必须控制：

- Prometheus 数据保留：本地 7 天 + 长期存储到对象存储
- 日志保留：分级，热数据 7 天/温数据 30 天/冷数据 6 个月归档到 OSS
- 高频指标限流（不需要每秒采集的不要采）
- 采样率合理（追踪 1% 即可）

月度预算（M3）：< ¥5000
月度预算（M12）：< ¥20000
```
