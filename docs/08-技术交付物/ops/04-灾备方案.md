# 灾备方案

## 一、灾备目标

- **RTO**（恢复时间）：< 1 小时
- **RPO**（数据丢失）：< 1 小时
- 可应对：单可用区故障、整区故障、人为误操作、勒索攻击

## 二、备份策略

### 1. MySQL 备份

```
全量备份：
  - 频率：每日 1 次（02:00 AM）
  - 工具：mysqldump / Xtrabackup
  - 存储：阿里云 OSS（跨区域复制）
  - 保留：最近 30 天 + 每月 1 个保留 12 个月

增量备份（binlog）：
  - 频率：实时（binlog 自动）
  - 保留：最近 7 天

延迟从库：
  - 1 个延迟从库（延迟 1 小时）
  - 防误操作（DROP / UPDATE 全表）

跨区复制：
  - 异地（华东 1）异步从库
  - 用于地理灾难
```

### 2. Redis 备份

```
RDB 快照：每小时
AOF 持久化：开启
存储：OSS 异地同步
注意：Redis 主要做缓存，可丢
```

### 3. OSS 文件

```
跨区域复制：开启
版本控制：开启（防误删）
保留：永久
注意：图片/视频/合同 PDF 等关键数据
```

### 4. ES 索引

```
快照：每日
存储：OSS
保留：30 天
```

### 5. 配置中心（Nacos）

```
备份：每日导出全量配置
存储：Git 版本管理
```

### 6. K8s 资源

```
Velero 备份：
  - 每日全集群备份
  - 包括 PVC、Secret、ConfigMap
  - 存储：OSS
```

## 三、恢复演练

### 1. 演练频率

| 场景 | 频率 |
|---|---|
| 单服务重启 | 每周自动 |
| MySQL 从库故障切换 | 每月 |
| Redis 集群单节点故障 | 每月 |
| 数据库全量恢复（测试库） | 每季度 |
| 跨区域灾备切换 | 每年 2 次 |

### 2. MySQL 恢复 SOP

#### 场景 A：误删表

```
T+0      事故发生
T+5min   暂停应用对该表的写操作（功能开关）
T+10min  从延迟从库（1h 延迟）查询数据快照
T+20min  导出快照
T+40min  应用到主库
T+50min  数据一致性校验
T+60min  恢复应用
T+24h    复盘 + 改进权限管控
```

#### 场景 B：主库宕机

```
T+0      监控告警
T+1min   SRE ack
T+5min   确认主库不可恢复
T+10min  从库提升为主库（手工或自动）
T+15min  应用连接切换
T+20min  恢复服务
```

#### 场景 C：整个数据库丢失

```
T+0      灾难发生
T+10min  评估范围 + 通知 CEO
T+30min  从最近全量备份恢复
         + 应用 binlog 增量
T+2-4h   完整恢复
T+24h    复盘
```

### 3. K8s 集群恢复

```
场景：整个 K8s 集群挂

方案：
  1. 用 Velero 备份重建集群
  2. 或：用 Terraform 重建基础设施 + Helm 重新部署
  3. 数据从 OSS 恢复

预计耗时：4-6h
```

### 4. 跨区域切换

```
触发条件：主区域整体不可用 > 30 分钟

步骤：
  1. 评估（10 分钟）
  2. CEO/CTO 决策
  3. DNS 切换到副区域（5 分钟生效）
  4. 副区域应用启动（10 分钟）
  5. 数据库主从切换（手工触发，30 分钟）
  6. 验证（30 分钟）
  7. 通知用户

总耗时：1-2 小时
```

## 四、勒索软件防御

```
1. 不可变备份：
   - OSS 版本控制 + 写保护
   - 备份系统独立账户/独立密钥
   - 主系统被攻破不影响备份

2. 网络隔离：
   - 备份存储与生产网络隔离
   - 通过专门 jump host 访问

3. 多份冷备：
   - 至少 1 份月度备份归档到独立账户
   - 物理隔离（云上不同 region + 不同账户）

4. 应急响应：
   - 立即断网隔离
   - 启用冷备恢复
   - 报警
```

## 五、数据一致性保障

```
分布式事务策略：
  - 强一致性场景：DB 事务（如订单+扣款）
  - 最终一致性：Saga / TCC / 消息事务

幂等设计：
  - 所有写接口必须幂等
  - 用业务幂等键（如订单号）

补偿机制：
  - 定时任务扫描异常状态
  - 自动重试 / 人工处理
```

## 六、合规与审计

```
备份审计：
  - 每月备份完成率 100%
  - 备份可恢复性测试（季度）
  - 备份保留期符合等保 2.0 要求

数据删除合规：
  - 用户申请删除：30 天内完成
  - 备份中的用户数据：单独标记，逐步淘汰

法律保留：
  - 涉案数据保留至判决后 3 年
  - 财务数据保留 10 年
```

## 七、演练剧本（季度）

### 剧本 1：MySQL 主从切换

```
准备：
  - 提前通知（仅 SRE 知道，CEO 不知道，测真实响应）
  - 准备时间：周末凌晨 2:00-4:00

注入：
  - 强制停止主库 mysqld

验证：
  - 自动切换是否成功
  - 应用是否自动重连
  - 主从延迟
  - 监控告警是否准确

完成：
  - 恢复原主库
  - 写复盘报告
```

### 剧本 2：K8s 节点故障

```
注入：
  - 关闭一个 K8s worker 节点

验证：
  - Pod 自动重新调度
  - 服务无中断
  - HPA 是否补充新副本
```

### 剧本 3：缓存全部丢失

```
注入：
  - 清空 Redis（仅测试环境）

验证：
  - 缓存穿透是否会击垮数据库
  - 限流是否生效
  - 业务是否退化（不挂掉）
```

## 八、灾备组织

```
灾备指挥部（DR Team）：
  - 总指挥：CTO
  - 数据库：DBA
  - 应用：SRE 负责人
  - 业务：产品总监
  - 沟通：CEO 助理（对外信息发布）

每次重大故障必须激活灾备指挥部。
```
