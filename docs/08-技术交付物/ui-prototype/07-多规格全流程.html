📊 单条 vs 多规格 对比

维度 ❌ 旧版（单条） ✅ 新版（多规格）
真实场景覆盖率 仅 20%（单条采购很少见） 100%（单条只是多规格的特例）
采购员发布效率 8 条要发 8 次（30 分钟+） 8 条一次发完（2 分钟）
卖家接单体验 收到 8 条孤立询价 看到完整需求，可建议合并优化
议价空间 单条单议，难有规模优惠 合并多行给同家，省运费/吨议价
对账复杂度 8 个会话 8 套报价 1 个会话清晰矩阵
最优组合 不可能（无全局视图） AI 自动算多卖家分单最优解

🛠 数据模型已经支持（无需改 DDL）

查 docs/08-技术交付物/db/01-schema.sql 中的 demand_cards 表：

CREATE TABLE demand_cards (
  card_id    VARCHAR(32) PRIMARY KEY,
  session_id VARCHAR(32),
  version    INT,
  items      JSON,        -- ⭐ 数组：[{productType, spec, quantity, ...}, ...]
  ...
);

后端的 DemandCard.items 字段（List<DemandItem>）从 v1 起就是数组。本次只调整 UI 把多规格作为默认，无需改后端。
