### 1.3 数据库压测

```sql
-- 高频读
SELECT * FROM market_references WHERE category=? AND material=? AND region=?
-- 目标 QPS: 500

-- 写入压力
INSERT INTO messages (...) VALUES (?, ?, ?)
-- 目标 QPS: 1000，P99 < 50ms

-- 复杂查询
SELECT s.*, ds.match_score, c.credit_score
FROM purchase_sessions s
JOIN dispatches ds ON s.session_id = ds.session_id
JOIN credit_scores c ON ds.seller_id = c.user_id
WHERE s.initiator_buyer_id = ? AND s.status IN ('matching','quoting')
ORDER BY ds.match_score DESC LIMIT 15
-- 目标 P99 < 200ms
```

### 1.5 监控指标

```
- API:
  - QPS（每秒请求数）
  - 延迟分布（P50/P95/P99/P999）
  - 错误率（4xx/5xx）

- 数据库：
  - 连接池利用率
  - 慢 SQL 数量
  - 主从延迟

- 缓存：
  - 命中率（目标 > 90%）
  - 内存使用

- 队列：
  - 堆积量
  - 消费延迟

- 服务器：
  - CPU < 70%
  - 内存 < 75%
  - 磁盘 IO
  - 网络带宽
```

### 1.6 性能基线 SLA

| 等级 | 标准 | 处理 |
|---|---|---|
| 绿色 | 全部达标 | 正常 |
| 黄色 | 任一 P95 超 1.5× 基线 | 告警 + 调研 |
| 红色 | 任一 P95 超 2× 基线 | 立即降级 + 扩容 |
| 紫色 | 错误率 > 5% | 紧急回滚 |

## 二、安全测试

### 2.1 OWASP Top 10 对照

| # | 风险 | 测试方法 |
|---|---|---|
| 1 | 注入（SQL/Command） | 工具扫描 + 手工 fuzz |
| 2 | 身份认证缺陷 | JWT 篡改 / Session 固定 / 弱密码 |
| 3 | 敏感数据泄露 | 数据传输是否加密 / 数据库是否加密 |
| 4 | XML 外部实体 | 不接受 XML 输入 |
| 5 | 访问控制缺陷 | 横向越权 / 纵向越权 |
| 6 | 安全配置错误 | 默认凭据 / 调试模式 / 不必要服务 |
| 7 | XSS | 前端输入过滤测试 |
| 8 | 不安全反序列化 | 限制反序列化类型 |
| 9 | 已知漏洞组件 | 依赖扫描（npm audit / mvn dependency-check） |
| 10 | 日志/监控不足 | 验证所有关键操作都有审计 |

### 2.2 身份认证安全测试

```yaml
- id: SEC-AUTH-001
  name: "JWT Token 篡改"
  steps:
    - 1: 正常登录获取 token
    - 2: 修改 payload 中的 user_id
    - 3: 用篡改 token 请求 API
  expected: 401 Unauthorized

- id: SEC-AUTH-002
  name: "Refresh Token 重放攻击"
  steps:
    - 1: 用同一个 refresh_token 调用两次刷新
  expected: 第二次返回 401

- id: SEC-AUTH-003
  name: "短信验证码爆破"
  steps:
    - 1: 请求验证码
    - 2: 用 100 个不同 code 尝试登录
  expected:
    - 5 次后触发图形验证码
    - 10 次后锁定 24h

- id: SEC-AUTH-004
  name: "微信登录 code 重放"
  steps:
    - 1: 用同一 code 调用两次 wechat-login
  expected: 第二次失败
```

### 2.3 数据隐私测试

```yaml
- id: SEC-PRIV-001
  name: "营业执照信息不泄露给同行"
  steps:
    - 1: 卖家 A 登录
    - 2: 访问其他卖家的详情接口
  expected:
    - 不返回法人身份证号
    - 不返回完整银行账号
    - 不返回未脱敏地址

- id: SEC-PRIV-002
  name: "虚拟号通话不泄露真实号码"
  steps:
    - 1: 买家拨打卖家虚拟号
    - 2: 检查双方 App 显示的来电号码
  expected: 双方都看到的是平台中继号

- id: SEC-PRIV-003
  name: "IM 内容关键词审核"
  steps:
    - 1: 发送含黑话的消息（"加微信"/"私下交易"）
  expected:
    - 触发 R024 跳单识别
    - 推送平台增值服务提醒
    - 但消息不被屏蔽（避免误伤）

- id: SEC-PRIV-004
  name: "数据导出权限"
  steps:
    - 1: 卖家 A 尝试导出卖家 B 的客户列表
  expected: 403 Forbidden
```

### 2.9 第三方安全审计

- **每年至少 1 次**全面渗透测试
- **每次大版本** 自动化扫描
- 通过 **个人信息保护法 / 数据安全法** 合规审查

### 2.10 安全等级

| 等级 | 标准 | 处理 |
|---|---|---|
| Critical | RCE / SQL 注入 / 任意文件读 | 24h 内修复 |
| High | 越权 / 敏感信息泄露 | 1 周内 |
| Medium | XSS / CSRF | 2 周内 |
| Low | 信息泄露（非敏感） | 下个迭代 |
