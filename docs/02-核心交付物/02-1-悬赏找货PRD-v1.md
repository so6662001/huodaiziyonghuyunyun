## 1. 背景与目标

### 1.1 业务背景
货袋子当前为单向"卖家发库存"展示型平台，买家侧无主动需求入口，导致买家访问后无沉淀、卖家收不到线索。

### 1.2 产品目标
构建买卖双向撮合的核心交易场景，让买家"30 秒发需求 → 30 分钟拿到多家报价"，同时为平台沉淀需求数据。

### 1.3 成功指标（北极星指标）
- **N1**：月有效撮合需求数 ≥ 3000（M3）
- **N2**：单需求 30 分钟有效报价数 ≥ 3 的占比 ≥ 70%
- **N3**：买家发起 → 主动联系卖家的转化率 ≥ 60%
- **N4**：自报成交率 ≥ 15%

### 1.4 非目标
- ❌ 不做在线支付/担保交易（V3）
- ❌ 不做电子合同（V2）
- ❌ 不做运费聚合（V2）
- ❌ 不做 AI 智能比价（V3）

## 4. 数据模型

```
Demand 需求表
├── demand_id (PK)
├── buyer_id (FK)
├── status (enum: draft|published|matching|quoting|closed|cancelled|expired)
├── product_category
├── material_grade
├── spec
├── quantity_ton (decimal)
├── delivery_city
├── delivery_district
├── delivery_date_range
├── payment_terms
├── note

├── bounty_amount
├── created_at, expired_at, closed_at
├── dispatched_count, quote_count, contact_count
└── deal_confirmed (bool)

Quote 报价表
├── quote_id (PK)
├── demand_id (FK)
├── seller_id (FK)
├── unit_price, include_freight, available_qty, valid_until
├── status (active|expired|withdrawn|won|lost)
├── created_at, viewed_by_buyer_at

Dispatch 派单表
├── dispatch_id (PK)
├── demand_id, seller_id
├── match_score, dispatch_channel
├── dispatched_at, seen_at, responded_at
└── response_status (quoted|rejected|ignored)

Contact 联系记录表
├── contact_id (PK)
├── demand_id, quote_id, buyer_id, seller_id
├── contact_type (im|virtual_call)
├── created_at, duration_seconds

Deal 成交回填表
├── deal_id (PK)
├── demand_id, quote_id, deal_amount
├── confirmed_by_buyer, confirmed_by_seller, confirmed_at
└── status (pending|confirmed|disputed)
```

### 状态机

```
需求：
draft → published → matching → quoting → closed
                            ↘ cancelled
                            ↘ expired

报价：
active → won
       ↘ lost
       ↘ expired
       ↘ withdrawn
```

## 6. 派单算法（伪代码）

```python
def dispatch(demand):
    # 1. 候选池筛选（硬条件）
    candidates = Seller.filter(
        category__contains=demand.product_category,
        status='active',
        is_blacklisted=False
    )

    # 2. 距离过滤
    candidates = candidates.filter(
        distance_to(demand.delivery_city) <= 500
    )

    # 3. 打分
    for s in candidates:
        s.score = (
            0.35 * category_match(s, demand) +
            0.20 * distance_decay(s, demand) +
            0.15 * activity_score_30d(s) +
            0.15 * credit_score(s) +
            0.10 * response_speed_score(s) +
            0.05 * recent_inventory_match(s, demand)
        )

    # 4. 上限控制
    sorted_list = sorted(candidates, key=lambda s: -s.score)
    sorted_list = filter_daily_quota(sorted_list)
    top_n = 30 if demand.priority == 'bounty' else 20 if 'urgent' else 15

    # 5. 多通道触达
    for seller in sorted_list[:top_n]:
        push_notification(seller, demand)
        if not seller.opened_in(5min):
            send_sms(seller, demand)
        if not seller.opened_in(15min):
            send_wechat_bot(seller, demand)

    # 6. 30 min 后兜底
    if demand.quote_count < 3 after 30min:
        expand_radius(demand, +200km)
        re_dispatch(demand)
```

## 7. 反作弊规则（核心 6 条）

```
R1: 设备指纹去重
  → 同设备 24h 内发需求 ≥ 3 条 → 人工审核

R2: 营业执照法人同源
  → buyer.legal_person == seller.legal_person → 屏蔽撮合

R3: 询价党监控
  → 30 日发需求 ≥ 30 条且自报成交 = 0 → 进入观察池

R4: 异常报价
  → 偏离市场参考价 ±15% → 标记，3 次进入限制池

R5: 同质化报价
  → 同需求多卖家报价方差 < 0.5% → 怀疑串价

R6: 高速响应异常
  → 卖家平均响应 < 5 秒 → 触发人机校验
```

## 9. 异常处理

| 场景 | 处理 |
|------|------|
| 24h 内 0 报价 | 自动延长 24h + 平台运营介入扩匹配 |
| 买家发后立即撤回 | 不扣悬赏费用 |
| 卖家报价后撤回 | 当日撤回 >3 次扣分 |
| 虚拟号无应答 | 自动转接备用号码 + 卖家收提醒 |
| 卖家库存售罄报价仍在线 | 报价 24h 不更新自动 expired |
| 系统故障 | 所有付费动作幂等，不重复扣费 |
